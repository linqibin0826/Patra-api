实现计划：patra-registry 容器化 + Mac mini 自托管 CD

📅 2026-06-07 🌿 worktree-setup-cd 📋 plan draft
面向 AI 代理的工作者： 必需子技能：使用 patra:subagent-driven-development（推荐） 或 patra:executing-plans 逐任务实现。 通过修改任务卡片与步骤的 data-status 属性追踪进度 （pending / in-progress / done / blocked / skipped）。 每完成一个 task 立即 commit。Task 4–7 涉及 GitHub Actions 触发与 Mac mini 实操， 验证依赖外部环境，步骤里已标注「谁执行 / 在哪执行」。
目标
把 patra-registry 容器化，并搭建一条到 Mac mini 的全自动 CD：merge main → 构建镜像推 GHCR → 常驻 Mac mini 的 self-hosted runner 拉取并用 OrbStack 部署。
架构
CI 用 Gradle 构建 bootJar 与 Docker 镜像、推送到公网 GHCR 作中转；Mac mini 上常驻的 self-hosted runner 接 deploy job，在 patra-net 内拉取并运行容器（容器内 nacos:8848 同网络直连、不经 tailscale，绕开 MacBook 跑应用时的 gRPC MTU/tunnel 痛点）；密钥按敏感度二分防公开仓库泄露。
技术栈
GitHub Actions · Docker / OrbStack · GHCR · eclipse-temurin:25-jre · Spring Boot prod profile · self-hosted runner (launchd)
关联 spec
Patra CD 流水线设计 — Mac mini 自托管持续部署（MVP: registry）

本计划聚焦 MVP：把 registry 一个服务的端到端 CD 链路（Dockerfile → 镜像 → GHCR → self-hosted runner → 部署 → 健康检查 → 回滚）打通，可独立产出可工作、可验证的软件。其余 4 个 Java 微服务与 portal 在 spec 的 Out of Scope，链路验证通过后复制同一模式，属后续独立计划。

任务 1：registry Dockerfile（本地构建验证）

创建

创建
patra-api/patra-registry/patra-registry-boot/.dockerignore
  1. 步骤 1：写 Dockerfile

    采用「CI 先 build jar → 镜像只 COPY」策略。registry 的 convention plugin 已设 bootJar.archiveClassifier="" 且禁用 plain jar，故 build/libs/ 下只有一个 fat jar，可用单文件通配 COPY。健康检查需要 curl，temurin jre 镜像默认不含，故 apt 安装。

    # patra-registry 运行镜像
# CI 已用 Gradle 构建好 bootJar（复用 Actions Gradle 缓存），这里只把 jar 装进精简运行镜像。
FROM eclipse-temurin:25-jre

# compose healthcheck 需要 curl（temurin jre 镜像默认不含）
RUN apt-get update \
    && apt-get install -y --no-install-recommends curl \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# bootJar 产物：archiveClassifier="" 且禁用 plain jar，build/libs 下只有一个 fat jar
COPY build/libs/*.jar app.jar

EXPOSE 6000

# 容器感知内存（temurin 25 默认开启 container support；显式给上限更稳）
ENTRYPOINT ["java", "-XX:MaxRAMPercentage=75.0", "-jar", "/app/app.jar"]
  2. 步骤 2：写 .dockerignore

    docker build context = registry-boot 目录，含庞大的 src/ 与 build/ 其他产物。只保留 build/libs 下的 jar，排除其余以加速。

    # 缩小 docker build context：只需要 build/libs 下的 fat jar
src/
.gradle/
build/classes/
build/generated/
build/resources/
build/tmp/
build/reports/
build/test-results/
  3. 步骤 3：本地构建 bootJar

    运行（仓库根）：./gradlew :patra-api:patra-registry:patra-registry-boot:bootJar

    预期：BUILD SUCCESSFUL；产物出现在 patra-api/patra-registry/patra-registry-boot/build/libs/patra-registry-boot-0.1.0-SNAPSHOT.jar（用 ls 确认只有一个 jar）。

  4. 步骤 4：本地构建镜像

    运行（仓库根）：

    docker build \
  -t patra-registry:local \
  patra-api/patra-registry/patra-registry-boot

    预期：镜像构建成功，最后输出 naming to docker.io/library/patra-registry:local。

  5. 步骤 5：冒烟验证镜像可启动

    无 DB/Nacos 时容器会启动到加载 prod 配置后失败退出——这是预期的；本步只验证「镜像本身可运行、能进入 Spring Boot 启动流程」。运行：

    docker run --rm -e SPRING_PROFILES_ACTIVE=prod \
  -e REGISTRY_DB_URL=jdbc:postgresql://localhost:5432/x \
  -e REGISTRY_DB_USERNAME=x -e REGISTRY_DB_PASSWORD=x \
  -e REGISTRY_REDIS_URL=redis://localhost:6379 \
  patra-registry:local 2>&1 | head -n 30

    预期：能看到 Spring Boot 启动横幅 / The following 1 profile is active: "prod" 之类日志，随后因连不上 DB 报错退出。看到启动横幅即通过。

  6. 步骤 6：Commit

        patra-api/patra-registry/patra-registry-boot/.dockerignore

任务 4：cd.yml — build-and-push job

创建
.github/workflows/cd.yml
  1. 步骤 1：写 cd.yml（先只含 build-and-push job）

    触发只监听 push:main 与 workflow_dispatch（不监听 pull_request，保证 self-hosted runner 不跑 fork 代码）。回滚（workflow_dispatch 指定 image_tag）时跳过 build，直接部署 GHCR 已有镜像。permissions.packages: write 让 GITHUB_TOKEN 能推 GHCR。Gradle 缓存沿用 CI 的 GRADLE_ENCRYPTION_KEY secret。

    name: CD

# 持续部署：merge 到 main（或手动触发）→ 构建 registry 镜像推 GHCR
#          → self-hosted runner 部署到 Mac mini。
# 安全：只监听 push:main 与 workflow_dispatch，不监听 pull_request，
#       保证 self-hosted runner 永不执行未经审查的 fork PR 代码。
on:
  push:
    branches: [main]
    paths:
      - 'patra-api/patra-registry/**'
      - 'patra-infra/docker/docker-compose.apps.yaml'
      - 'patra-infra/docker/.env.apps'
      - '.github/workflows/cd.yml'
  workflow_dispatch:
    inputs:
      image_tag:
        description: '要部署的镜像 tag（留空=构建并部署本次 commit；回滚时填旧 sha）'
        required: false
        default: ''

concurrency:
  group: cd-${{ github.ref }}
  cancel-in-progress: false

env:
  IMAGE_NAME: ghcr.io/linqibin0826/patra-registry

jobs:
  build-and-push:
    name: build-and-push
    # 回滚（指定了 image_tag）时跳过构建，直接部署 GHCR 已有镜像
    if: github.event_name == 'push' || github.event.inputs.image_tag == ''
    runs-on: ubuntu-latest
    timeout-minutes: 20
    permissions:
      contents: read
      packages: write
    steps:
      - name: 📥 Checkout
        uses: actions/checkout@v4

      - name: ☕ Setup JDK 25 (Temurin)
        uses: actions/setup-java@v4
        with:
          java-version: '25'
          distribution: 'temurin'

      - name: 🐘 Setup Gradle
        uses: gradle/actions/setup-gradle@v4
        with:
          cache-encryption-key: ${{ secrets.GRADLE_ENCRYPTION_KEY }}

      - name: 🔨 Build bootJar
        run: ./gradlew :patra-api:patra-registry:patra-registry-boot:bootJar

      - name: 🔑 Log in to GHCR
        run: echo "${{ secrets.GITHUB_TOKEN }}" | docker login ghcr.io -u ${{ github.actor }} --password-stdin

      - name: 🐳 Build & push image
        run: |
          TAG="${{ github.sha }}"
          CTX="patra-api/patra-registry/patra-registry-boot"
          docker build -t "$IMAGE_NAME:$TAG" -t "$IMAGE_NAME:latest" "$CTX"
          docker push "$IMAGE_NAME:$TAG"
          docker push "$IMAGE_NAME:latest"
  2. 步骤 2：Commit

任务 5：Mac mini self-hosted runner 安装

创建
patra-infra/scripts/install-github-runner.sh
  1. 步骤 1：写 install-github-runner.sh

    在 Mac mini 上下载 runner、注册到仓库、装成 launchd 常驻服务。registration token 由用户运行时传入（绝不写死/提交）。关键：runner 以非交互方式跑时 PATH 不含 OrbStack 的 docker（见 patra-infra/CLAUDE.md 非显性约束 #2），用 runner 的 .path 文件显式补 /usr/local/bin。

    #!/usr/bin/env bash
# 在 Mac mini 上安装 GitHub Actions self-hosted runner 为常驻服务（launchd）。
# ============================================================
# 用法（在 Mac mini 上运行）：
#   1. GitHub 仓库 → Settings → Actions → Runners → New self-hosted runner，
#      复制其中的 registration token（约 1 小时有效）。
#   2. bash patra-infra/scripts/install-github-runner.sh <REGISTRATION_TOKEN>
# runner labels 固定 self-hosted,macmini（cd.yml 的 deploy job 据此选中）。
set -euo pipefail

TOKEN="${1:?用法: install-github-runner.sh <REGISTRATION_TOKEN>}"
REPO_URL="https://github.com/linqibin0826/patra"
RUNNER_VERSION="2.328.0"   # 如失效查 https://github.com/actions/runner/releases 用最新版
RUNNER_DIR="$HOME/actions-runner"
ARCH="osx-arm64"           # Apple Silicon Mac mini
TARBALL="actions-runner-${ARCH}-${RUNNER_VERSION}.tar.gz"

mkdir -p "$RUNNER_DIR"
cd "$RUNNER_DIR"

if [ ! -f "./config.sh" ]; then
  echo "==> 下载 runner ${RUNNER_VERSION} (${ARCH})"
  curl -fSL -o "$TARBALL" \
    "https://github.com/actions/runner/releases/download/v${RUNNER_VERSION}/${TARBALL}"
  tar xzf "$TARBALL"
  rm -f "$TARBALL"
fi

# 关键：非交互运行时 PATH 缺 OrbStack docker；runner 会读工作目录 .path 覆盖 PATH
echo "/usr/local/bin:/opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin" > .path

echo "==> 注册 runner 到 $REPO_URL"
./config.sh --url "$REPO_URL" --token "$TOKEN" \
  --name "macmini" --labels "macmini" --unattended --replace

echo "==> 安装为 launchd 服务并启动"
./svc.sh install
./svc.sh start
./svc.sh status

    说明：--labels "macmini" 即可，runner 会自动附带内置 self-hosted 标签，故 cd.yml 的 runs-on: [self-hosted, macmini] 能命中。

  2. 步骤 2：Commit 脚本 
    git add patra-infra/scripts/install-github-runner.sh
git commit -m "feat(cd): 新增 Mac mini self-hosted runner 安装脚本 (PAP-CD)"
  3. 步骤 3：在 Mac mini 上安装 runner（用户实操）

    把脚本同步到 Mac mini（如 Mac mini 的仓库副本 git pull），并在 Mac mini 上执行（<TOKEN> 替换为 GitHub 页面给出的 registration token）：

    # 在 Mac mini 上（ssh linqibin@linqibins-mac-mini 后）
bash ~/Projects/patra/patra-infra/scripts/install-github-runner.sh <TOKEN>

    预期：svc.sh status 显示服务 started。

  4. 步骤 4：验证 runner 在线且能访问 docker

    ① GitHub → Settings → Actions → Runners，确认 macmini 状态为 Idle / online，labels 含 self-hosted, macmini。

    ② 在 Mac mini 上确认 runner 环境能找到 docker：

/usr/local/bin/docker version --format '{{.Server.Version}}'  # 预期打印 OrbStack 引擎版本
