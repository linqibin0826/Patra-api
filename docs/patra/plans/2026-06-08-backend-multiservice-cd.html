后端多服务 CD 实现计划

📅 2026-06-08 🌿 worktree-cd-backend-multiservice 📋 plan draft
面向 AI 代理的工作者：用户授权 overnight 自主执行（inline）。用 patra:executing-plans 逐任务实现，改 data-status 追踪，每任务 commit。完成后 PR + admin merge + CD 验证 + 出汇报 HTML。守住安全红线（公开仓库，外部 API key 进 .secret）。
目标
把 object-storage / catalog / ingest / gateway 接入已有 Mac mini self-hosted CD（registry 已完成），实现选择性多服务构建与部署。
架构
单 cd.yml：detect-changes 算改动服务 → 动态 matrix 只 build/push 改动的 → 单 deploy job 循环部署。5 服务共用一份分层 Dockerfile + services.json SSOT。含「改公共面→重建全部」正确性规则。
技术栈
GitHub Actions（matrix / fromJson / self-hosted runner）· Docker（多阶段分层 jar）· docker compose · jq · Spring Boot 4
关联 spec
后端多服务 CD 设计

任务 6：cd.yml 重写 + detect-changes.sh

创建
patra-infra/cd/detect-changes.sh
修改
.github/workflows/cd.yml
  1. 步骤 1 — detect-changes.sh：入参 BEFORE/AFTER（或 dispatch service）。逻辑：dispatch 指定服务→该服务（或 all→全部）；BEFORE 全零→全部；否则 git diff --name-only 逐文件匹配 services.json 的 srcPrefix→命中服务；命中 ignore（patra-portal/ docs/ .claude/ patra-infra/scripts/ patra-infra/CLAUDE.md *.md）→跳过；既不属任何服务也不在 ignore（公共模块/build-logic/gradle/根 build/共享 Dockerfile/compose/.env.common/cd.yml）→ rebuild all。输出紧凑 JSON 数组。用 jq 读 services.json。
  2. 步骤 2 — cd.yml job detect-changes：checkout（fetch-depth 适配 diff）→ 调 detect-changes.sh → outputs.services。
  3. 步骤 3 — job build-and-push：strategy.matrix.service: ${{ fromJson(needs.detect-changes.outputs.services) }}，if services 非空；setup-java 25 + gradle（读 services.json 取 gradleTask）→ docker build -f patra-infra/docker/service.Dockerfile --build-arg APP_PORT={port} {context} → 推 :{sha} + :latest。
  4. 步骤 4 — job deploy（self-hosted，单 job 循环）：沿用 registry 已验证机制（DOCKER_CONFIG auths 绕钥匙串 + 软链 cli-plugins）。读改动服务列表，循环：set {SVC}_IMAGE_TAG → compose pull {svc}（重试3）→ compose up -d {svc} → 轮询该服务端口 /actuator/health。object-storage 优先（catalog/ingest 依赖它）。
  5. 步骤 5：触发 paths 扩到 patra-api/** + patra-gateway-boot/** + linqibin-commons/** + patra-starters/** + build-logic/** + gradle/** + settings/build.gradle.kts + patra-infra/docker/** + patra-infra/cd/** + cd.yml。workflow_dispatch 输入 service+tag。commit。
