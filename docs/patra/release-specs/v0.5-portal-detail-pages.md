## 1. 版本目标 / 价值

访客在 Patra 首页点开任一**期刊**或**文献卡片**，能进入对应详情页：

- **期刊详情页** —— 看到该期刊的简介与元信息（刊名 / 出版商 / ISSN / 影响力指标等）。**不含**该刊收录文献列表（留待检索页跳转）。
- **文献详情页** —— 看到这篇文献的完整元信息（标题 / 作者 / 摘要 / 期刊来源 / 年份 / 标识符等）。

两页各自打通首页已有的真实数据入口。

**验证场景**：
- 首页期刊模块点一个期刊 → **期刊详情页**（看简介，无文献列表）；
- 首页 explore-feed 点一篇文献 → **文献详情页**（看完整元信息）。

全程数据真实、视觉按 hi-fi 稿落地。

## 3. 范围边界（不做的事）

| # | 不做的事 | 理由 |
|---|---------|------|
| A | 期刊详情页不内嵌"该刊收录文献列表" | "看该刊文献"留到检索页跳转（带期刊筛选），本版不在期刊详情页内嵌列表 |
| B | AI 速读不接真实 LLM | 文献详情页 `aiSummary` 继续留空/mock；真实 LLM 接入是独立大任务，本版不做 |
| C | 收藏 / 用户系统 | 两个详情页的"⭐ 收藏"为静态 mock，不触发后端；无登录/用户体系 |
| D | 检索结果页 / 主题聚合页 / 期刊聚合页 | 本版只做"期刊详情 + 文献详情"两页，其余浏览页不做 |
| E | i18n / 暗色模式 / 主题切换 | 继续单一中文 light theme，本版不做 |
| F | 详情页内部模块的最终形态不在此锁定 | "详情页放哪些模块"由 Issue 0 产品定义 + Design 决定，本字段只锁版本级边界 |

## 4. 关键决策

### A. 数据契约由产品/设计驱动，不被现有列表 DTO 框死

- **影响 Issue**：0 1 2 3 4 5 6（全部）
- **判断规则**：跨层级（Product/Design/BE/FE）+ 影响 ≥2 Issue
- **决策**：锁定顺序 **Product → Design → BE → FE**。Issue 0 产品定义 + Design hi-fi 先确定"详情页呈现哪些信息"，BE 再据此暴露字段；**不**以现有 `PortalVenueResponse`（6 字段）/ `PortalPaperResponse` 的字段集为设计上限。设计所需数据若 DB 已有（摘要 / 封面 / 结构化作者 / 各类 JSON 指标）→ BE 仅需开端点暴露；若 DB 也没有 → 在对应 BE Issue 内显式标注缺口（本版默认优先用已有数据，不主动延伸采集）。

### B. 详情走新建 by-id 端点 + 独立 detail DTO

- **影响 Issue**：3 4 5 6
- **判断规则**：跨 ≥2 Issue + 难逆（DTO/端点形态定后 FE 全依赖）
- **决策**：新建 `GET /portal/venues/{id}` 和 `GET /portal/publications/{id}`，各配**独立** `PortalVenueDetailResponse` / `PortalPaperDetailResponse`（字段远多于列表 DTO）。**不**扩现有列表 DTO、**不**复用列表端点；列表端点保持精简不动。

### C. URL 用 journals/papers，BE 端点保持 venues/publications

- **影响 Issue**：3 4 5 6 + 首页入口
- **判断规则**：跨 ≥2 Issue（命名贯穿 BE 路径 + FE 路由 + 入口链接）
- **决策**：面向用户的 FE 路由用 `/journals/[id]`、`/papers/[id]`；BE 端点保留领域语义 `venues`/`publications`；FE 客户端层延续既有 venue→Journal / publication→Paper 命名桥接（portal 已有"前端零字段映射"先例）。

> **已排除出本字段**（属项目规约或 Issue 层）：RSC 服务端优先（portal CLAUDE.md 已定）、详情页 404/错误态（Issue 层 AC）、Claude Design handoff 机制（沿用 v0.4 决策 A：prompt 直发 + zip 快照备份）。
