## 1. 版本目标 / 价值

访客在 Patra 门户能**浏览/检索期刊**，并从首页或列表点开任一**期刊**或**文献**进入对应页：

- **期刊浏览/检索页** `/journals` —— 浏览全部期刊，按刊名检索、按指标排序、按学科/分区/OA 筛选；补齐首页"浏览全部期刊"的落点。
- **期刊详情页** `/journals/[id]` —— 该期刊的简介与元信息（刊名 / 出版商 / ISSN / 影响力指标等）。**不含**该刊收录文献列表（留待检索页跳转）。
- **文献详情页** `/papers/[id]` —— 这篇文献的完整元信息（标题 / 作者 / 摘要 / 期刊来源 / 标识符等）。
- **全局状态屏**（404 / 错误页）—— 全站此前缺失，本版随设计一并产出为可复用资产。

三页统一走全站策略：**服务全体用户 + 渐进式披露**（默认层 + 深数据层，见决策 D）。

**验证场景**：
- 首页"浏览全部期刊" → **期刊浏览/检索页** → 搜索/排序/筛选 → 点期刊卡片 → **期刊详情页**；
- 首页 explore-feed 点一篇文献 → **文献详情页**（看完整元信息，期刊名可回跳期刊详情）。

全程数据真实、视觉按 hi-fi 稿落地。

## 3. 范围边界（不做的事）

| # | 不做的事 | 理由 |
|---|---------|------|
| A | 期刊详情页不内嵌"该刊收录文献列表" | "看该刊文献"留到检索页跳转（带期刊筛选），本版不在期刊详情页内嵌列表 |
| B | AI 速读不接真实 LLM | 文献详情页 `aiSummary` 继续留空/mock；真实 LLM 接入是独立大任务，本版不做 |
| C | 收藏 / 用户系统 | 详情页的"⭐ 收藏"为静态 mock，不触发后端；无登录/用户体系 |
| D | **文献检索结果页 / 主题聚合页 / 文献列表页** | 本版做**期刊**的浏览/检索（`/journals`），不做**文献**的检索结果页（首页文献检索框维持 teaser，结果页 future）；文献的浏览靠首页 explore-feed，不单做文献列表页 |
| E | i18n / 暗色模式 / 主题切换 | 继续单一中文 light theme，本版不做 |
| F | 详情/列表页内部模块的最终形态不在此锁定 | "页面放哪些模块"由 PAP-39 产品定义 + Design 决定，本字段只锁版本级边界 |

> **边界 D 的调整**：原 D 把"期刊聚合页"列在不做里；本版**将其移出、纳入范围**（即 `/journals` 期刊浏览/检索页）。期刊检索与文献检索是不同实体的检索路线，互不重叠（见决策 E）。

## 4. 关键决策

### A. 数据契约由产品/设计驱动，不被现有列表 DTO 框死

- **影响 Issue**：全部
- **决策**：锁定顺序 **Product → Design → BE → FE**。PAP-39 产品定义 + Design hi-fi 先确定"页面呈现哪些信息"，BE 再据此暴露字段；**不**以现有 `PortalVenueResponse`（6 字段）/ `PortalPaperResponse` 的字段集为设计上限。设计所需数据若 DB 已有 → BE 仅需开端点暴露；DB 缺失 → 在 BE Issue 内显式标注缺口（设计简报附录 A 已给出"理想字段 → 数据现状"映射）。

### B. 详情走新建 by-id 端点 + 独立 detail DTO；BE 合并为单 Issue

- **影响 Issue**：PAP-42 / 44 / 45 / 47
- **决策**：新建 `GET /portal/venues/{id}` 和 `GET /portal/publications/{id}`，各配**独立** `PortalVenueDetailResponse` / `PortalPaperDetailResponse`（字段远多于列表 DTO）；列表端点 `GET /portal/venues` 在原基础上**扩展**分页/排序/检索/筛选（供 `/journals`）。**不**扩详情 DTO、**不**复用列表端点形态做详情。三个端点的实现**合并到单个 BE Issue（PAP-42）**。

### C. URL 用 journals/papers，BE 端点保持 venues/publications

- **影响 Issue**：PAP-42 / 44 / 45 / 47 + 首页入口
- **决策**：面向用户的 FE 路由用 `/journals`、`/journals/[id]`、`/papers/[id]`；BE 端点保留领域语义 `venues`/`publications`；FE 客户端层延续既有 venue→Journal / publication→Paper 命名桥接。

### D. 全站策略：服务全体用户 + 渐进式披露

- **影响 Issue**：全部页面（Design + FE）
- **决策**：门户面向所有类型用户，不为单一人格裁页面；统一**渐进式披露**——默认层给核心信息、深数据层按需展开。已沉淀进 `patra-portal/CLAUDE.md`（含 BE 连带含义：详情端点一次返回完整数据集供前端按需披露）。

### E. 期刊检索 ≠ 文献检索

- **影响 Issue**：PAP-46 / 47（+ 边界 D）
- **决策**：本版做**期刊**浏览/检索（`/journals`：刊名检索 + 排序 + facet 筛选）；**文献**检索结果页仍 future。两者搜的是不同实体，职责不重叠；首页文献检索框维持现状。

> **已排除出本字段**（属项目规约或 Issue 层）：RSC 服务端优先（portal CLAUDE.md 已定）、详情页 404/错误态（Issue 层 AC + 全局状态屏）、Claude Design handoff 机制（沿用 v0.4：prompt 直发 + zip 快照备份）。
