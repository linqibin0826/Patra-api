Patra 学习站（patra-learn）设计规格

📅 2026-08-27 🌿 feat/patra-learn-site 👤 linqibin 🎯 spec draft
关键决策摘要

把 Claude Design 画布「Patra 学习站」（方向 A 六类页面 + 独立设计系统）落地为工作区新子项目 patra-learn。技术栈与 patra-portal 同栈（Next.js 15 / React 19 / TS strict / Tailwind v4），内容采用「类型化 TS 数据 + 每站一个 TSX 文章」模式，不引入 MDX / CMS。v1 一次交付完整六类页面与 CI/CD 全部 13 站内容（迁移自「上线线路图」手册）。学习进度存读者浏览器 localStorage。部署为 Mac mini 上的新容器（端口 4001，仅 tailscale 内网），完整复用现有 CD 流水线模式（mini 原生构建 + deploy.sh 闭环）。

1. 背景与现状

CI/CD 原生化改造完成后，产出了两份学习资产：图解手册「上线线路图」（Artifact）与设计画布「Patra 学习站」（Claude Design 画布 e2bb7c08，含方向 A 六类页面高保真稿 + 独立设计系统 Tokens/Components 页）。画布已确认为建站蓝本，但它只是设计稿——本规格把它变成真实网站：新成员入门、自己回顾、未来扩展新学习主题（架构线、数据线）都在这个站上进行。

现状约束：工作区已有 patra-portal（Next.js 15 成熟工程模板）与 patra-infra（CD 流水线：mini 原生 arm64 构建 → deploy.sh 健康检查/回滚闭环 → GHCR 归档），学习站应最大化复用两者，不新增基建概念。

2. 范围边界

In Scope
  • 新子项目 patra-learn/：Next.js 15 工程（配置照抄 portal 模式）
  • 六类页面全部实现：首页网络图 / 课程页 / 名词图鉴 / 事故档案馆 / 操作小抄 +（信息架构由路由体现）
  • CI/CD 全内容：3 条线 13 站文章（迁移自「上线线路图」手册）、10 词条、6 档案、3 操作卡
  • 画布设计系统 → Tailwind v4 @theme token（中性 7 阶 / 线路色 5 / 语义色 3 / Noto Sans SC 900 + JetBrains Mono）
  • localStorage 学习进度打卡与首页点亮
  • 部署接入：Dockerfile、compose 服务、services.json 条目、learn-cd.yml 工作流
  • 内容完整性测试 + 进度库单测 + Playwright 冒烟
Out of Scope
  • 4 号线（架构线）、5 号线（数据线）的文章内容——首页仅以「规划中」虚线呈现
  • 账号体系 / 服务端进度同步（进度仅存浏览器）
  • 公网暴露（仅 tailscale 内网；不做内容脱敏）
  • 全文搜索服务（图鉴搜索为客户端数组过滤）
  • CMS / MDX / 后台编辑（内容即代码，改内容走 PR）
  • 与 claude.ai/design 的组件同步（design-sync 已决策推迟）

3. 架构与目录

与 patra-portal 并列的独立 pnpm 项目，全站 SSG 静态生成（generateStaticParams 枚举 13 站），仅进度相关组件为 client component。工程配置（Biome / Vitest / Playwright / tsconfig / husky / lint-staged）从 portal 复制后按项目名调整。

4. 设计系统落地

画布 Tokens/Components 页（page-3）是唯一视觉规范来源，转成 Tailwind v4 @theme CSS 变量：

  • 色板：中性色 7 阶（bg #FAFAF8 → ink #22262C）；线路色 L1 #2E66C9 / L2 #D95B32 / L3 #7A5FB8 / L4 #1E8E7E / L5 #B0498C（各配 +12% 明度 soft 变体）；语义色 成功 #2C9457 / 提醒 #B98014 / 危险 #CC4747。
  • 字体：next/font 内置 Noto Sans SC（400/500/700/900，900 为「站牌黑」标题）+ JetBrains Mono（代码/编号）。构建期自托管，运行时零外部字体请求（内网可用性）。
  • 验收铁律：吸取 portal 教训（@theme 语义 token 未映射导致死类）——每个 token 必须有对应可编译的 utility，DS 落地任务的测试是「用 token utility 写的样式在构建产物中非空」。
  • 核心组件（照 Components 画板）：LineChip（线路徽章）、StationNode（站点节点：实心已学 / 空心未学 / 圆环当前）、StationBadge（站牌标题）、ResourceCard（词条/档案/操作卡三种变体）、CodeBlock（小抄命令块 + 复制按钮）、MetroMap（首页 SVG 网络图）。

本设计系统与 portal 的 DS 相互独立（已决策）：共享工程习惯（Tailwind v4 / token 化），隔离视觉语言。

5. 内容模型与站点拓扑

内容即代码，两种形态：结构化数据（typed const）与文章组件（TSX）。核心类型：

type StationRef = `${LineId}/${string}`            // 如 'l2/native-build'
type Station = { id: string; name: string; summary: string }
type Line = {
  id: 'l1' | 'l2' | 'l3' | 'l4' | 'l5'
  name: string; theme: string; color: string
  status: 'open' | 'planned'
  stations: Station[]                               // planned 线也列站名，仅展示
}
type GlossaryEntry = { term; analogy; explain; appearsAt: StationRef[] | 'all' }
type Incident = { no; tag; title; story; lesson; relatedStation: StationRef }
type OpsCard  = { action; scenario; command; note; lineColor }

v1 拓扑（源自画布 Main/Sitemap 画板，站名以 Sitemap 完整版为准）：

线路主题站点（order 即顺序）
1 号线 · 质检线合并前的门禁考试（CI）写代码 → 开 PR → 只考改过的 → 并行考试（4 站）
2 号线 · 上线线合并后的自动部署（CD）mini 领任务 → 本机打包 → 部署闭环 → 健康检查 → 上线与回滚（5 站）
3 号线 · 守夜线每日自动巡检每天 07:00 → 查岗与钥匙 → 四项体检 → 通知哲学（4 站）
换乘节点「合并进 main」：连接 1 号线终点与 2 号线起点的视觉节点，不计入 13 站、无独立文章，点击滚动至 2 号线
4 / 5 号线status: 'planned'：首页灰色虚线 + 站名灰点，不可点击（架构线 3 站 / 数据线 2 站站名已定）

互链网络：词条的 appearsAt、档案的 relatedStation 都是 StationRef，由内容完整性测试保证不断链；课程文章正文中的术语用 <Term> 组件包裹跳转图鉴。13 站正文从「上线线路图」手册逐站迁移（手册章节 → 站的映射表在实现计划中给出）。

6. 六类页面

  • 首页 /：顶栏（站名 + 搜索占位 + 进度徽章「已到 N/13 站」）；MetroMap SVG 网络图（3 条开通线按线路色、已学站实心、当前站圆环、规划线虚线）；「继续通勤 →」卡片指向第一个未打卡站；底部三个全局资源入口卡。
  • 课程页 /lines/[line]/[station]：站牌标题（900 黑体 + 线路徽章）、本线站点条（当前站高亮）、TSX 正文（SVG 图解 + <Term> 术语链）、文末打卡按钮、上一站/下一站导航。
  • 名词图鉴 /glossary：10 词条卡片墙（术语 + ≈Java 类比 + 解释 + 「出现于」线路色 chip 回链）；顶部客户端过滤搜索框。
  • 事故档案馆 /archive：6 档案卡（红色档案编号 tag + 故事 + 绿色「→ 于是有了」教训 + 相关站回链）。
  • 操作小抄 /cheatsheet：回滚 / 巡检 / 升级三张命令卡（场景说明 + mono 命令块 + 复制按钮）+ 两条红线提示（任务执行中禁重启 runner；RUNNER_ADMIN_TOKEN 不可删）。
  • 信息架构：Sitemap 画板不单独成页，它就是以上路由结构本身。

7. 进度机制

  • src/lib/progress.ts：读写 localStorage key patra-learn.progress.v1（已打卡 StationRef 数组）；所有读写包 try/catch，异常时按零进度渲染。
  • 课程页文末「✓ 我学完这一站了」打卡按钮，可再点取消；打卡状态驱动首页 MetroMap 点亮、进度徽章、「继续通勤」目标（第一个未打卡站，全通则显示完成态）。
  • 纯客户端、每浏览器独立；服务端渲染时按零进度出静态 HTML，客户端 hydrate 后点亮（注意避免 hydration mismatch：进度渲染放 useEffect 后）。

8. 部署与 CD 接入

完全复制 portal 模式，动四处、不新增基建概念：

  1. patra-learn/Dockerfile：照抄 portal 的 multi-stage standalone 构建，容器端口 4001。
  2. patra-infra/docker/ compose：新增 patra-learn 服务（网络/暴露策略与 portal 内网部分一致，仅 tailscale 可达）。
  3. patra-infra/cd/services.json：新增条目 { name: "patra-learn", port: 4001, healthPath: "/api/health", gradleTask: null }；deploy.sh 的 ORDER 末尾追加 patra-learn——健康检查、last-good、自动回滚机制零改动自动生效。
  4. .github/workflows/learn-cd.yml：从 portal-cd.yml 复制，路径过滤 patra-learn/**，mini 原生构建 arm64 镜像 → deploy.sh → GHCR 归档（best-effort）。CI 侧同样复制 portal 的 lint/typecheck/test 工作流模式。

9. 测试策略（TDD）

  • 内容完整性测试（Vitest，核心防线）：所有 StationRef（词条 appearsAt / 档案 relatedStation）指向真实开通站；每个开通站的文章组件文件存在且可 import；线路/站点/词条/档案 id 无重复；开通站总数 = 13。加内容的 TDD 循环：先写引用与数据 → 测试红 → 补文章 → 绿。
  • 进度库单测：打卡 / 取消 / 重复打卡幂等 / localStorage 抛异常时降级为零进度。
  • Playwright 冒烟（3 条）：首页渲染 13 个站点节点；课程页打卡 → 返回首页站点点亮 → 刷新仍点亮；图鉴搜索输入后卡片过滤生效。
  • Biome + tsc --noEmit 进 pre-commit（husky + lint-staged，同 portal）。

关键决策与备选

决策 1：v1 一次交付六类页面 + CI/CD 全内容

不做「先壳后内容」的分期。内容源（上线线路图手册）已完备，绿地项目按最终形态交付。

备选 A：先做壳走通部署，内容后补 — 否决：上线时站点是半成品，且内容迁移并无技术风险，分期是伪需求。
备选 B：额外做「配置化扩线」抽象 — 否决：YAGNI；数据驱动的内容模型本身已让加线 = 加数据 + 加文章，无需更多抽象。

决策 2：与 portal 同栈，内容用「类型化 TS 数据 + TSX 文章」

Next.js 15 照抄 portal 工程模式；结构化内容为 typed const，课程正文每站一个 TSX 组件。作者是"你 + Claude"，markdown 写作便利是伪收益；文章价值在自定义 SVG 图解，TSX 是最直接表达。

备选 A：Astro + MDX — 否决：引入第二套前端栈，与 portal 工程心智割裂；交互（网络图/打卡）本就需要 island，静态优势被抵消。
备选 B：Next.js + MDX — 否决：图解密集场景下 MDX 嵌组件比直接写 TSX 绕，且 Next 15 + RSC 的 MDX 工具链仍有摩擦。

决策 3：学习进度 = 读者个人进度，存 localStorage

每个读者各自打卡各自点亮，符合「学习站」语义；无账号无后端。

备选 A：进度写死在内容数据里（内容建设进度）— 否决：所有人看到同一张图，失去「我的通勤」体验；线路的 planned 状态已承载内容建设维度。
备选 B：两层叠加（发布状态 × 个人打卡逐站叠加）— 否决：v1 开通线全部有文章，站级发布状态无信息量，只留线级 status 即可。

决策 4：仅 tailscale 内网暴露

与其他 patra 服务一致；事故档案含运维细节（机器名、密钥名、红线），不对公网可见，因此内容无需脱敏。

备选 A：经 cloudflare tunnel 公开（如 portal）— 否决：需先内容脱敏，且受众（自己 + 未来新成员）本就在内网准入范围。

决策 5：部署为独立容器 + 独立 CD 工作流（learn-cd.yml）

复制 portal-cd.yml 而非在其中加分支逻辑：两个前端项目的构建/部署生命周期独立，工作流文件一一对应更清晰，watchdog / deploy.sh 无需感知差异。

备选 A：合并进 portal-cd.yml 用 matrix — 否决：路径过滤与失败隔离变复杂，违背现有「一服务一工作流」模式。
备选 B：静态导出 + nginx 容器 — 否决：需要新的镜像模式与健康检查方式，next start standalone 已是现成闭环，省的那点内存不值得引入第二种部署形态。

风险与缓解

风险等级缓解
13 站正文迁移工作量大，页面质量参差 mid 手册「上线线路图」已含全部内容与图解结构；实现计划中给出手册章节 → 站的逐站映射表，每站独立任务独立验收
Tailwind v4 @theme token 落地成死类（portal 踩过） mid DS 任务的验收即「token utility 在构建产物中非空」；发现映射不全时改 @theme 定义而非 arbitrary value 绕行
localStorage 进度导致 hydration mismatch low 进度渲染统一放客户端 effect 后；SSG 输出恒为零进度态；Playwright 冒烟覆盖「打卡 → 刷新仍点亮」
首页 SVG 网络图布局复杂，实现偏离画布视觉 mid MetroMap 数据驱动（从 lines.ts 生成），布局常量对照 Main.dc.html 逐值校准；开发期浏览器对照画布验收
新 CD 工作流首跑失败阻塞（新镜像名 / compose 服务未就位） low 接入顺序固定：先合入 compose + services.json 并在 mini 手动 deploy 验证一次，再启用 learn-cd.yml；deploy.sh 回滚机制兜底
