期刊浏览/检索页 /journals 设计文档

📅 2026-06-07 🌿 pap-47-fe-journals-browse-page 👤 Lin 🎫 PAP-47 🎯 spec draft
关键决策摘要

实现期刊浏览/检索页 /journals，全栈任务，忠实复刻 PAP-46 hi-fi 稿（封面网格 + 刊名检索 + 4 维排序 + 多选 facet 筛选 + 页码分页）。核心约束：真实库有 15,434 本期刊，原型那套「全量拉到客户端现算 facet」不成立，必须服务端渲染 + URL-as-state。为忠实还原 hi-fi 的「每选项实时计数 + 多选 + present-options」，后端补 faceted-search：GET /portal/venues 扩多值筛选，新增 GET /portal/venues/facets 返回 drill-down 计数（按当前 query+其他维度算，排除本维度）。前端用两层 Suspense——网格 keyed-Suspense 出骨架（补 hi-fi 缺的翻页骨架），筛选面板稳定-key Suspense 平滑更新（保留移动端 sheet 打开态、不随翻页重算 facet）。「学科」facet 用真实 jcr_rating.subject（英文细分 ~250 类，做成组内可搜索）。补两处 hi-fi gap（首屏空库态、翻页骨架网格），修 JournalCoverCard 的 IF null 守卫。

1. 背景与现状

v0.5 Portal Detail Pages 里程碑下，PAP-44（期刊详情 #133）、PAP-45（文献详情 #135）已交付，沉淀了「零映射 wire type + 纯函数 derive 视图层 + RSC 取数」模式。PAP-47 是本里程碑的浏览页——补齐首页「浏览全部期刊」按钮的落点（当前 <button disabled>，Journals.tsx:37-44）。

前置依赖均已就绪：PAP-42（BE portal 读端点 #132）已提供 GET /portal/venues 分页/单值筛选/4 维排序读链路（VenueBrowseReadAdapter 单次 LATERAL JOIN 取最新年 JCR/CAS，无 N+1）；PAP-46（hi-fi 稿）已定稿，原型在 ~/Downloads/patra-portal-v0.5-handoff（journals-browse.jsx / journals-data.jsx / journals.css）。

原型与真实数据的根本错位（本设计的核心动因）：hi-fi 原型对 ~27 本 mock 在浏览器内现算 facet 计数/多选/present-options；真实库 15,434 本（实测 total），不可能整包送客户端，且现有端点是单值筛选、不返回计数也不返回可选值清单。经决策：全忠实 · 扩 BE——后端补 faceted-search 能力，前端服务端渲染完整还原 hi-fi。原型已替我们定下两件事：分页是页码分页（pageWindow + ‹/› + "第 X–Y 本"），facet 计数语义是 drill-down（matchAll(except=group)，组内多选不互相清零）。

真实数据要点（实测）：jcrQuartile="Q1".."Q4"，casMajorQuartile="1区".."4区"（与原型 JCR_QUARTILES/CAS_ZONES 对得上）；jcr_rating.subject 是英文大写细分（ONCOLOGY，约 250 类），cas_rating.major_category 是中文粗类（医学/生物学，约 18 类），hi-fi 想要的中文细分领域在库里不存在——「学科」facet 决策为用 jcr_rating.subject（英文细分，组内可搜索）；country_code 数据稀疏（样本为 null）。

3. 架构总览：服务端渲染 + URL-as-state

15k 本 → 必须服务端。/journals 走 RSC 读 searchParams → 服务端取数 → 渲染；所有交互控件（client）只改 URL，URL 变触发 RSC 重渲染。天然可分享/可回退、零客户端数据缓存。这是 portal 第一个列表+分页+URL 同步页面。

三块 Suspense 策略（关键，决定交互手感）：

区域挂载导航行为理由
检索/排序控件 JournalSearchSortControlsclient，始终挂载（在所有 Suspense 之外）不重挂，输入框保持焦点防抖检索时输入流畅、光标不丢
筛选面板 JournalFiltersServer→JournalFiltersasync RSC，包稳定-key Suspense首次显骨架；后续导航 React transition 保留旧面板就地换新计数（不闪 fallback、不重挂）移动端 sheet 打开态保留、组内搜索文本/滚动不丢；facet 仅随筛选变、不随翻页重算
结果区 JournalResults（命中数 + 网格 + 分页）async RSC，包keyed Suspense（key=完整 query）任意 query 变（含翻页）→ key 变 → 强制出骨架网格补 hi-fi 缺的翻页骨架（gap②）

为让「筛选面板不随翻页重算」「结果网格随翻页出骨架」，facet 与分页拆成两个后端端点 + 两次取数：facet 取数 key 不含 page（翻页时 key 不变 → 不重取、不重挂）；结果取数含完整 query。

交互→URL 约定：检索输入用 router.replace（防抖 300ms，不污染历史）；离散动作（排序、facet 勾选、翻页、移除 chip）用 router.push（可回退到上一状态）。任意筛选/检索/排序变更都 reset page=1。

4. 后端：faceted-search 扩展（catalog）

4.1 两个端点

  • GET /portal/venues（扩展）：返回结构不变（PageResult<PortalVenueBrowseResponse>，首页 fetchVenues 不受影响），仅把单值筛选扩成多值 IN + 新增 oa 布尔。
  • GET /portal/venues/facets（新增）：入参为筛选维度（q + 各 facet，不含 page/pageSize/sort），返回 PortalVenueFacetsResponse（drill-down 计数 + present-options）。

4.2 筛选维度 → 真实列映射

facet / 参数真实列（LATERAL 取最新年）语义多值
qcat_venue.title（+ abbreviated_title）前缀 LIKE（现有 ESCAPE '!' 转义保留）—
subject（学科）cat_venue_jcr_rating.subject英文 JCR 学科，IN✓
jcr（JCR 分区）cat_venue_jcr_rating.jif_quartileQ1..Q4，IN✓
cas（中科院分区）cat_venue_cas_rating.major_quartile1区..4区，IN✓

oa（仅开放获取，新增）cat_venue.open_access->>'isOa'（JSONB）布尔（"仅开放获取"）—
doajcat_venue.open_access->>'isInDoaj'（JSONB，现有）布尔—
country（国家/地区）cat_venue.country_code两位码，IN✓

4.3 base CTE + drill-down 计数

page 查询与 facet 查询共用一段 base（venue + 最新年 JCR/CAS LATERAL JOIN + OA 字段从 JSONB 提取），保证两端口径一致。计数语义 = drill-down（排除本维度自身）：对每个 facet 维度 G，计数在「q + 除 G 外所有已选维度」的集合上做 GROUP BY——这样组内多选不会把自己其它选项清零（与原型 matchAll(except=group) 一致）。

  • 4 个分组维度（subject/jcr/cas/country）：各一条 GROUP BY 计数查询，返回 {value, count}[]。
  • 3 个布尔维度（casTop/oa/doaj）：各一条 COUNT WHERE（在「q + 其他维度」集合上，该布尔为真的条数）。
  • present-options：分组维度只返回库中实际存在的取值；显示侧按 count 降序，count=0 灰显但保留（值存在于全集）。

本版按清晰度优先用多条查询实现（最多 7 条聚合，15k 行 + 现有索引可接受）；单条 GROUPING SETS 合并是可选的后续优化，记为 tradeoff，不在本版。

4.4 六边形落点

  • domain：VenueBrowseFilter 单值 → List<String>（subject/jcr/cas/country）+ 加 Boolean isOpenAccess；新增 VenueBrowseFacets 读模型（4 列表 + 3 计数）；VenueBrowseReadPort 加 facets(VenueBrowseFilter) 方法（或新建 VenueFacetsReadPort）。
  • app：PortalVenueBrowseQueryService 编排 page 查询；新增 facets 查询编排（CQRS 读端无接口）。
  • infra：VenueBrowseReadAdapter 改多值 IN + 实现 facets；VenueDao 加 base CTE 与 facet 聚合原生 SQL；新增 VenueFacetCountRow 投影。
  • adapter：PortalVenueListRequest 改多值参数（List<String> / CSV）+ 加 oa；新增 PortalVenueFacetsResponse + facets 端点方法；PortalApiConverter 加 facets 映射。

4.5 测试（TDD，./gradlew check 门控）

  • VenueBrowseReadAdapterIT（@DataJpaTest + TestContainers）：多值 IN 筛选、oa/doaj 布尔、facet drill-down 计数（验「选 Q1 后 JCR 组其它分区计数不归零」）、present-options、空库（facets 全空 + page total=0）。

7. URL 契约

示例：/journals?q=lancet&sort=cited&page=2&subject=ONCOLOGY,CARDIAC%20%26%20CARDIOVASCULAR%20SYSTEMS&jcr=Q1,Q2&cas=1区&casTop=1&oa=1&doaj=1&country=US,GB

  • 多值用逗号分隔；布尔用 1；默认值省略（sort=if / page=1 / 空 / false 不写入）。

  • page 越界（> 总页数）由服务端 clamp 到末页（与原型 Math.min(f.page, pageCount) 一致）。

关键决策与备选

决策 1：全忠实 · 扩 BE 做 faceted-search（而非简化 facet）

真实 15k 本 + hi-fi 的 drill-down 计数/多选/present-options，只能靠后端补 faceted-search 来忠实还原。GET /portal/venues 扩多值筛选 + 新增 /facets 端点返回 drill-down 计数。

备选 A：前端全量拉到客户端现算（照搬原型）— 否决：15k×16 字段约 6MB/次，不可行。
备选 B：简化 facet（单值、无计数、硬编码枚举）— 否决：明显弱于已批准 hi-fi，用户明确选「全忠实」。

决策 2：facet 与分页拆两端点 + 两层 Suspense

facet 计数与「看第几页」无关，拆 /portal/venues（分页）+ /portal/venues/facets（计数）。前端 facet 取数 key 不含 page → 翻页不重算 facet、面板不重挂；结果区 keyed-Suspense → 翻页/筛选出骨架（补 gap②）。

备选 A：单端点 facets=true 内嵌响应 — 否决：facet 会随翻页一起重算，且难让「面板平滑、网格出骨架」分别成立。
备选 B：全用 keyed-Suspense（含面板）— 否决：移动端 sheet 一勾选就重挂关闭、组内搜索/滚动丢失。

决策 3：「学科」facet 用 jcr_rating.subject（英文细分）

hi-fi 想要中文细分领域，真实数据没有。两套真实字段：JCR subject（英文细分 ~250）vs CAS major_category（中文粗类 ~18）。选 JCR subject——粒度贴近 hi-fi，组内做可搜索消化长列表。

备选 A：CAS 大类（中文 ~18）— 否决：太粗（多数医学期刊都=医学，不具区分度）。
备选 B：两个都做 — 否决：facet 面板变长、两套口径，超出本版必要。

决策 4：drill-down 计数语义（排除本维度自身）

每维度计数在「q + 除本维度外其它已选维度」集合上算。这样组内多选不会把自己其它选项清零（选 Q1 后仍看得到 Q2/Q3/Q4 还有多少）。与原型 matchAll(except=group) 一致。

备选：在「含本维度」的全过滤集合上算 — 否决：选一个值后同组其它值计数全归零，多选体验崩坏。

决策 5：页码分页 + 服务端渲染（沿用原型 + RSC）

原型用 pageWindow 页码分页；与 RSC「每页一次服务端渲染、可分享/回退」最契合。分页用 <Link>（纯服务端导航，无需客户端 JS）。

备选：load-more 累加 — 否决：客户端累积状态与服务端渲染/回退还原打架。
