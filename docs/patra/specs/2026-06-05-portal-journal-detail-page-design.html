期刊详情页 /journals/[id] — 设计文档

📅 2026-06-05 🌿 pap-44-fe-journal-detail-page 👤 linqibin 🎫 PAP-44 🎯 spec draft
关键决策摘要

在 src/app/journals/[id]/ 以 RSC 服务端取数实现期刊详情页，消费 PAP-42 的 GET /portal/venues/{id} 端点。VenueDetail 类型直接贴 BE 扁平响应（零运行时映射），hi-fi 原型只取其 UI 形态、不照搬 mock 数据结构；UI 上 BE 顶层未给的字段（学科领域 / 百分位 / 排名 / CiteScore / 语言）由 FE 派生纯函数从评级列表 + 顶层字段组装，推不出的（关联学会）按"缺失即隐藏"降级。取数走 RSC 直取（沿用首页 Journals.tsx 模式，不引 TanStack Query）；404 → notFound()，其他失败 → throw 冒泡到全局 error.tsx。本 issue 连带落地全站可复用的 not-found.tsx / error.tsx 状态屏（供 PAP-45 文献页复用），并解除首页期刊卡片 disabled 接通跳转。

1. 背景与现状

Patra 门户（patra-portal，Next 15 App Router / React 19 / Tailwind v4）首页已上线，期刊模块（Journals.tsx + JournalCoverCard.tsx）已接入真实数据，但期刊卡片当前是 <button disabled> 占位（"功能即将上线"），点击无跳转。后端 PAP-42 已合并，暴露 GET /patra-catalog/portal/venues/{id}，返回 PortalVenueDetailResponse——一个专为前端零映射设计的扁平响应 + 评级列表结构（id 为 String 避免 JS 精度损失，顶层摊平最新值快照，深层评级以 jcrRatings[]/casRatings[]/scopusRatings[]/yearlyStats[]/identifiers[] 列表给全量明细）；不存在的 id 由后端抛 VenueNotFoundException → CATALOG-0404。

Claude Design 已交付 v0.5 详情页 hi-fi（handoff zip 内 detail-pages.jsx / detail-shared.jsx / detail.css + patra-ds-cards/ 组件卡 + 截图），确立了 masthead + 影响力速览 + 渐进式披露折叠区 + 双栏布局的视觉与交互。本 issue 的工作是把已定稿的 hi-fi UI 落到 Next 代码，并接通首页 → 详情页跳转闭环。

2. 范围边界

In Scope
  • src/app/journals/[id]/page.tsx（RSC 服务端取数）+ loading.tsx + not-found.tsx
  • fetchVenueDetail(id) + VenueDetail 类型（贴 BE 扁平响应）+ 派生纯函数 venue-derive.ts
  • 按 hi-fi 落地期刊详情组件（masthead / 影响力速览 / 定位 / 折叠深数据层 / 侧栏速览）
  • 全站可复用状态屏：src/app/not-found.tsx + src/app/error.tsx + portal/status/ 基元
  • 首页 JournalCoverCard 解除 disabled，接 Link → /journals/[id]
  • 派生函数 + 关键组件 Vitest 单测 + Playwright smoke
Out of Scope
  • 期刊页不含该刊文献列表（边界 A）
  • 暗色模式（边界 E，单一 light theme）
  • 首页"浏览全部期刊"按钮——保留 disabled，留给 PAP-47（期刊浏览页 /journals）
  • 回头修改 BE 补字段（affiliatedSocieties/languages[] 等本版用现有字段或隐藏）
  • 侧栏"边界说明卡"为 v0.5 占位文案，非真实功能
  • 文献详情页 /papers/[id]（PAP-45）

4. 数据契约与 FE 组装

VenueDetail 类型贴 BE 扁平响应（src/types/portal.ts，零运行时映射，与现有 VenueBrowse 风格一致）。顶层为"最新值快照"（影响力速览 + 侧栏直接用），评级列表给深数据层全量明细：

export interface VenueDetail {
  id: string;
  title: string;
  abbreviatedTitle: string | null;
  venueType: string | null;
  issnL: string | null;
  countryCode: string | null;
  primaryLanguage: string | null;
  foundedYear: number | null;
  coverObjectKey: string | null;
  homepageUrl: string | null;        // BE 恒 null → 主操作降级
  isOpenAccess: boolean | null;
  // 顶层"最新值"快照
  impactFactor: number | null;
  jcrQuartile: string | null;
  jcrSubject: string | null;
  casMajorCategory: string | null;
  casMajorQuartile: string | null;
  casIsTop: boolean | null;
  citeScore: number | null;
  hIndex: number | null;
  citedByCount: number | null;
  worksCount: number | null;
  frequency: string | null;
  medlineIndexed: boolean | null;
  oaType: string | null;
  apcUsd: number | null;
  isInDoaj: boolean | null;
  // 完整评级列表（深数据层明细 + 派生来源）
  jcrRatings: JcrRating[];
  casRatings: CasRating[];
  scopusRatings: ScopusRating[];
  yearlyStats: YearlyStat[];
  identifiers: VenueIdentifier[];
}

子类型 JcrRating / CasRating / ScopusRating / YearlyStat / VenueIdentifier 各字段一一对应 BE 子 record（见 PortalVenueDetailResponse）。

FE 派生规则（hi-fi UI 要、但 BE 顶层未直接给的，从列表/顶层派生；纯函数集中到 venue-derive.ts，组件只消费派生结果，不在 JSX 散落 .find()/.sort()）：

hi-fi UI组装来源推不出时降级
定位 · 学科领域标签jcrSubject + casMajorCategory 去重拼两者皆空 → 标签不显
速览卡 percentile / rankjcrRatings 取 year 最大项的 jifPercentile / jifRank空列表 → 不显该行
Scopus 速览 CiteScore顶层 citeScore（BE 已摊平）或 scopusRatings 最新年null → 第 3 卡退中科院 / 不显
收录 · 语言primaryLanguage 单值（BE 无 languages[]）null → 不显
关系 · 关联学会无 BE 来源整块隐藏（不占位）

字段级降级总则（沿用 hi-fi）：无封面 → 占位框；某套评级缺失 → 该模块隐藏不占位；无趋势 → 趋势区不显；无 APC → 不显；homepageUrl 为 null → 主操作 disabled + title 提示"官网链接待采集"；ISSN 占位值 "XXXX-XXXX" 过滤不显。

6. 错误流与状态屏

错误流：

  • fetchVenueDetail(id) 收到 BE 404（CATALOG-0404）→ 返回 null → page 调 notFound() → 命中 [id]/not-found.tsx
  • fetch 其他失败（5xx / 超时 / 网络）→ throw → 冒泡到全局 error.tsx（Next error boundary）
  • 坏 URL（如 /journals/abc，非数字 id）→ BE @Positive 拒绝（422）或 fetchVenueDetail 提前判定非法 → notFound()

状态屏（连全局一起落地，供 PAP-45 复用）：

  • portal/status/NotFoundState.tsx：暖纸插画 + Patra 人格文案 + 返回首页（RSC）
  • portal/status/ErrorState.tsx：可读错误提示 + 重试按钮 + 返回首页（"use client"，不暴露堆栈）
  • src/app/not-found.tsx + src/app/error.tsx：全局薄壳，包 State 基元
  • src/app/journals/[id]/not-found.tsx：期刊专属文案，复用 NotFoundState

8. 关键决策与备选

决策 A：VenueDetail 类型贴 BE 扁平响应，零运行时映射

TS 类型镜像 PortalVenueDetailResponse 的扁平 + 评级列表结构，与现有 VenueBrowse/venues.ts 风格一致。hi-fi 原型只取 UI 形态（布局、降级态、视觉），其 mock 数据结构（metrics.jcr.* 嵌套）和代码框架不照搬。

备选 A：写 mapVenueDetail() 把扁平响应还原成 hi-fi 嵌套结构 — 否决：多一层映射 + 一套嵌套类型要维护，YAGNI 反模式；BE 已为前端零映射设计，再加 mapper 是倒退。

决策 B：BE 顶层缺失字段在 FE 派生组装，推不出则隐藏，不回头改 BE

hi-fi UI 要的学科领域 / 百分位 / 排名 / CiteScore / 语言，绝大多数能从评级列表 + 顶层字段派生（集中到 venue-derive.ts 纯函数）；affiliatedSocieties 无 BE 来源 → 整块隐藏。本版不为补字段反推 BE。

备选 A：拆 BE 小补丁另开 issue 补 affiliatedSocieties[]/languages[] — 否决：BE 端点刚定稿，能覆盖 ~95% UI；缺的两个字段非核心信号，"缺失即隐藏"已是 hi-fi 既定降级策略，不阻塞 FE。

决策 C：RSC 服务端直取，不引 TanStack Query

沿用首页 Journals.tsx 的 await fetchX() 模式。详情页纯展示、无客户端交互取数，RSC 直取是 Next 官方等价路径，也是 portal 既有约定。

备选 A：客户端 TanStack Query 取数 — 否决：详情页无需客户端缓存/重取/乐观更新，引 Query 反增 client bundle 与水合成本，违背 RSC 优先。

决策 D：404 走 notFound()，其他失败 throw 到全局 error.tsx

fetchVenueDetail 区分 404（返回 null → notFound()）与其他失败（throw → Next error boundary）。两类失败映射到两个不同状态屏，符合 AC"id 不存在→not-found / 取数失败→error 页"。

备选 A：所有失败统一渲染同一错误页 — 否决：丢失 404（资源不存在）与 5xx（服务异常）的语义区别，用户无法分辨是"刊不存在"还是"系统挂了"。

决策 E：状态屏连全局一起落地，基元供 PAP-45 复用

本 issue 顺带实现全站 not-found.tsx / error.tsx + portal/status/ 基元（hi-fi 已设计为全站复用资产）。略超 PAP-44 的最小 AC，但 PAP-45 文献页能直接复用，避免重复。

备选 A：只做期刊页自己的 [id]/not-found.tsx + loading，全局屏留后续 — 否决：PAP-45 紧接其后也要 404/error，分两次做必然重写；hi-fi 已出全站稿，一次到位最省。

决策 F：首页"浏览全部期刊"保留 disabled，留给 PAP-47

本 issue 只解除期刊详情卡片（JournalCoverCard）的 disabled 接通 /journals/[id]。"浏览全部期刊"指向 /journals 列表页（PAP-47 范围），现在接 Link 会 404，故保留 disabled 由 PAP-47 一并解除。

备选 A：本 issue 就把"浏览全部"接 Link → /journals — 否决：/journals 列表页尚不存在，点击即 404 断链，体验劣化；职责应留在 PAP-47。

9. 风险与缓解

风险等级缓解
BE 详情端点真实数据中评级列表为空 / 字段大面积 null，触发大量降级，页面显得空 mid 派生函数 + 组件全程 null-safe；smoke 用真实 BE 数据跑一遍肉眼核对；降级态本就是 hi-fi 一等设计目标，非异常
hi-fi 原型 mock 字段（嵌套 metrics.*）与 BE 扁平字段语义对不齐，组装逻辑写错 mid 派生逻辑全部纯函数 + Vitest 单测覆盖（含取最新年、拼接、降级分支）；不在 JSX 散落取数逻辑
homepageUrl BE 恒 null，主操作"访问官网"长期 disabled，hi-fi 主 CTA 形同虚设 low 已知约定（BE 注释明确恒 null 待采集）；按 hi-fi 降级为 disabled + title 提示，不阻塞页面；待采集补齐后零改动生效
RSC 中 fetch 区分 404 vs 5xx 处理不当，导致 error boundary / notFound 错触发 low fetchVenueDetail 显式判 res.status === 404 返 null、其余 !res.ok throw；smoke 覆盖不存在 id 路径
