Portal 首页期刊模块接入真实数据

📅 2026-06-01 🌿 feat/portal-journals-real-data 🎯 spec draft
关键决策摘要

将 portal 首页「高影响力期刊」模块从 6 条硬编码 mock 替换为 catalog 真实数据。新增 catalog GET /portal/venues 端点，按影响因子降序取 Top 6，走与现有 publication portal 端点完全一致的 CQRS 读链路；返回 id / name / abbr / impactFactor / quartile / foundedYear。前端 Journals 改为 async RSC 拉真实数据，JournalCoverCard 封面改为前端生成式、卡片右下「本周收录」位换成 JCR 分区标签，并删除 data/journals.ts mock。本轮范围仅期刊；Hero 统计与话题云各自后续独立 PR。

1. 背景与现状

patra-portal 首页由 4 个模块组成：文献流（已于 #114 接入 catalog 真实数据）、Hero 统计、话题云、期刊。后三者目前仍是前端硬编码 mock。本次处理「期刊」模块。

当前 src/components/portal/Journals.tsx 直接 import { JOURNALS }，数据来自 src/data/journals.ts 中 6 本顶级期刊（NEJM / Lancet / JAMA 等）的硬编码常量，其 impact、weekly 均为虚构值。catalog 后端已落库完整期刊数据（cat_venue 中 15,434 本 JOURNAL、cat_venue_jcr_rating 影响因子），但尚未对外暴露任何期刊 REST 端点—— catalog 当前唯一的 portal 端点是 GET /portal/publications。

真实数据现状（决定设计的硬约束，均经 SQL 核验）：

  • JOURNAL 共 15,434 本；有影响因子的仅 670 本（4.3%）。
  • JCR 影响因子数据按字母只爬到 A 段（670 中 614 本 A 开头）：NEJM / Lancet / Nature / JAMA / CA 当前 impact_factor 全为 null。按影响因子排序，首页 Top 当前必然是 Annals of oncology(65.4) 等 A 开头刊。用户将同步补爬 JCR 数据，端点逻辑不变，数据补全后门面自动改善。
  • weekly「本周收录」无法实现：全部 18,807 篇文献的 created_at 集中在 2026-05-31 一小时内（同批导入），时间窗聚合零区分度。
  • 可用字段覆盖率：abbreviated_title 100%、publication_profile.startYear（创刊年）98%、wos_overall_quartile（最新年）100%、jif_quartile 仅 78%。

2. 范围边界

In Scope
  • catalog 新增 GET /portal/venues，完整 CQRS 读链路（照 publication portal 1:1）。
  • 按影响因子降序取 Top 6（topN 参数，默认 6）。
  • 前端 Journals 模块接入真实数据并删除 mock。
  • JournalCoverCard 封面生成式 + 右下换 JCR 分区标签 + 文案数字修正。
Out of Scope
  • Hero 统计、话题云模块（各自后续独立 PR）。
  • 期刊详情页 / 全量期刊浏览（卡片点击保持 disabled）。
  • JCR 影响因子数据补全（用户单独爬，属数据层任务）。
  • 期刊封面图 image_object_key 接入（仅 670 本有图，覆盖率低）。

3. 后端设计

端点：GET /patra-catalog/portal/venues（经 gateway StripPrefix=1 转发至 catalog /portal/venues）。查询参数 topN（可空，默认 6，上限约 50，Bean Validation 收敛 4xx）。

取数：cat_venue 中 venue_type='JOURNAL' 且未软删，LEFT JOIN LATERAL 取每刊最新年 cat_venue_jcr_rating（ORDER BY year DESC LIMIT 1），按 impact_factor 降序，取前 N。该 LATERAL JOIN 写法直接复用 VenueDao.findFilteredJournalPage 现成模板。Top N 为首页固定列表，不分页，读链路统一用 List 传递。

调用链（与 PortalPublicationController 那条 1:1 对齐）：

PortalVenueController            (adapter)  GET /portal/venues
  → PortalVenueQueryService       (app, 无接口)   归一化 topN，委托 ReadPort
    → PortalVenueReadPort         (domain port/read)  List<PortalVenueReadModel> findTopByImpactFactor(int topN)
      → PortalVenueReadAdapter    (infra adapter/read, @Repository)
        → VenueDao#findTopVenuesByImpactFactor  (native query + LATERAL JOIN)
          → PortalVenueRow        (Spring Data 接口投影)
  ← PortalVenueReadModel          (domain model/read/portal)
  ← PortalApiConverter#toVenueResponse → PortalVenueResponse

数据契约（PortalVenueResponse，record，YAGNI 只给卡片用得上的字段）：

关键决策与备选

决策 1：排序 = 影响因子降序，670 池（不按文献过滤）

按最新年影响因子降序取 Top 6，符合医学领域期刊展示惯例（LetPub / MedSci / Web of Science 均按 JIF + 分区）。不以「是否有库内文献」做过滤。

备选 A：限「有影响因子 ∩ 有文献」288 池 — 否决：用户明确「不需要看有没有文献」。
备选 B：按库内收录文献数排序（2924 池）— 否决：非医学惯例，顶部是 Int J Mol Sci 等大体量 OA 水刊，不构成门面。

决策 2：卡片右下「本周收录」位换为 JCR 分区

用 wos_overall_quartile（最新年，100% 覆盖）展示 Q1–Q4 分区标签，与影响因子绝配，是医学期刊最通行的标签。

备选 A：库内收录篇数 — 否决：语义偏弱，非期刊门面惯例。
备选 B：移除该数据位 — 否决：卡片右下视觉留空、不平衡。
注：分区选 wos_overall_quartile 而非 jif_quartile，因前者 100% 覆盖、后者仅 78%。

决策 3：后端走完整 CQRS 读链路（照 publication）

新建 9 个类 1:1 对齐现有 publication portal 端点，SQL 复用 VenueDao 现成 LATERAL JOIN。绿地项目一致性优先，CQRS 读端口清晰，为期刊详情/筛选等后续扩展留基础。

备选：轻量复用 VenueDao、跳过 domain ReadPort — 否决：少写约 4 个类，但破坏与 publication 端点的架构一致性，CQRS 读端口缺失。

决策 4：封面走前端生成式

封面文字由 abbr 派生，配色按 id hash 从预设深色调色板选取，统一视觉。后端 image_object_key 不接入。

备选：接入后端 image_object_key 真实封面图 — 否决：仅 670 本有图，覆盖率低且风格不一，生成式更统一可控。

风险与缓解

风险等级缓解
JCR 数据按字母只爬到 A 段，首页 Top 偏 A 开头刊，NEJM/Lancet 等暂缺。 mid 用户同步补爬 JCR 数据；端点逻辑与数据解耦，补全后门面自动改善，无需改码。
foundedYear 从 publication_profile JSON 解析可能 null 或结构缺失。 low 后端解析失败返回 null；前端 null 时隐藏 est. 行，不报错。
impactFactor 为 numeric，BigDecimal 序列化精度/格式。 low Response 统一 BigDecimal → JSON number；展示精度由前端 toFixed(1) 控制。
Top 6 可能同为 Q1，分区标签区分度低。 low 可接受：分区是行业标准标签而非排序键，与影响因子数值互补。
