文献详情页 /papers/[id] 设计文档

📅 2026-06-06 🌿 pap-45-fe-paper-detail-page 👤 Lin 🎫 PAP-45 🎯 spec draft
关键决策摘要

实现文献详情页 /papers/[id]（RSC），忠实复刻 PAP-41 hi-fi 稿，并接通 explore-feed 文献卡片「详情」入口。架构沿用 PAP-44 期刊详情页：零映射 wire type + 纯函数 derive 视图层 + 复用既有基元（NotFoundState / ErrorState / DisclosureSection / IdentifierChip / SectionEyebrow / portal-ui）。这是一个全栈任务：先把后端 PortalPublicationDetailResponse 模型补齐（新增 source / fullTextUrl 两个真实字段 + bookmarks / estimatedReadMin 两个诚实占位字段，仿照现有 aiSummary 恒 null 占位先例），再前端落地。无真实用户，缺数据字段一律 null/0 + TODO，以后再填，绝不向用户展示伪造数据。

1. 背景与现状

v0.5 Portal Detail Pages 里程碑下，PAP-44 已交付期刊详情页 /journals/[id]（已合并 #133），沉淀了一批可复用的详情页基元与「零映射 wire type + derive 视图层」模式。PAP-45 是它的姊妹页——文献详情页 /papers/[id]。

前置依赖均已就绪：PAP-42（BE portal 读端点，含文献详情 by-id）已合并 #132，提供 GET /patra-catalog/portal/publications/{id}；PAP-41（文献详情 hi-fi 稿）已定稿，快照在 docs/patra/design/snapshots/2026-06-06-detail-pages-hifi.zip。当前 explore-feed 的 PaperCard「详情」按钮是 <button disabled> 占位（PaperCard.tsx:69-78），文献流可浏览但点不进详情。

调研发现 hi-fi 的右侧「速览」卡需要 5 项数据（证据等级 / 被引数 / 收藏数 / 阅读时间 / 来源），以及 header 的「去全文」按钮需要原文链接，而当前详情 DTO 只给得出证据等级与被引数。经决策：后端模型要齐全——能接真实数据的字段接出来，暂无数据的留 null/0 + TODO 占位，与列表端点 PortalPaperResponse 已有的 bookmarks=0、estimatedReadMin=null 及详情 DTO 已有的 aiSummary=null 占位先例保持一致。

2. 范围边界

In Scope
  • BE：PortalPublicationDetailResponse 补齐 4 字段（source/fullTextUrl 真实，bookmarks/estimatedReadMin 占位）+ 读链路 SQL/ReadModel/Converter 扩展 + IT 扩测
  • FE：PaperDetail wire type + 子类型，fetchPublicationDetail(id)，publication-derive.ts derive 层
  • FE：文献专用组件（EvidenceBadge / AbstractBlock / AuthorList / PaperHeader / PaperRail / BookmarkButton / PublicationDetailView）
  • FE：路由 app/papers/[id]/{page,loading,not-found}.tsx
  • FE：PaperCard「详情」解除 disabled，接 Link 到 /papers/[id]
  • 收藏按钮 + AI 速读区按 mock 占位渲染（边界 B/C）
  • 测试：fetch 分支 / derive 纯函数 / 组件 / 卡片 link / Playwright smoke
Out of Scope
  • 真实收藏系统 / 用户系统（无用户，本版只 mock 交互）
  • 真实 AI 速读生成（无 LLM 接入，aiSummary 恒 null）
  • 阅读时间真实估算（无全文/字数数据，estimatedReadMin 留 TODO）
  • OA 多位置（cat_publication_oa_location）聚合——本版只用 cat_publication_metadata.full_text_url 单一原文链接字段
  • 文献被引趋势图 / 相关文献推荐（BE 无对应读模型）
  • 期刊列表页 /journals（留 PAP-47）

3. 后端：补齐详情模型

详情读链路：PortalPublicationController.getDetail → PortalPublicationDetailQueryService.getById → PublicationDetailReadPort → PublicationDetailReadAdapter（PublicationDetailDao 原生 SQL 投影 PublicationDetailRow）→ PublicationDetailReadModel → PortalApiConverter.toPublicationDetailResponse → DTO。DTO 不经领域聚合，直接由读模型投影装配。

PortalPublicationDetailResponse 新增 4 字段，命名对齐列表端点 PortalPaperResponse（API 一致性）：

字段类型来源 / 处理real / 占位
source String cat_publication.provenance_code（主查询已 FROM 该表，SQL 加一列），经 PortalApiConverter.toSource() 转人类可读（如 "PubMed"） real
fullTextUrl String cat_publication_metadata.full_text_url（1:1），SQL 加 LEFT JOIN cat_publication_metadata real
bookmarks Integer 无收藏系统，Converter 直接置 0（对齐列表 bookmarks=0 // 无用户系统）+ TODO 占位
estimatedReadMin Integer 无全文/字数数据，Converter 直接置 null（对齐列表同名字段 TODO）+ TODO 占位

改动落点：

  • PublicationDetailDao 原生 SQL：SELECT 加 p.provenance_code；FROM 后加 LEFT JOIN cat_publication_metadata m ON m.publication_id = p.id，SELECT 加 m.full_text_url
  • PublicationDetailRow（投影接口）：加 provenanceCode、fullTextUrl getter
  • PublicationDetailReadModel：加 provenanceCode、fullTextUrl 字段
  • PortalApiConverter.toPublicationDetailResponse：builder 加 4 行——.source(toSource(model.provenanceCode())) / .fullTextUrl(model.fullTextUrl()) / .bookmarks(0) / .estimatedReadMin(null)，后两者带 // TODO 注释，仿照已有的 .aiSummary(null) // TODO
  • bookmarks/estimatedReadMin 不入 ReadModel/SQL，仅在 Converter 层置占位值

测试（TDD，./gradlew check 门控）：

  • PortalPublicationControllerIT（@WebMvcTest + mock QueryService）：在 fixture builder 加字段值，jsonPath 断言 $.source / $.fullTextUrl，$.bookmarks isEqualTo 0，$.estimatedReadMin isEmpty()（仿 $.aiSummary）
  • PublicationDetailReadAdapterIT（@DataJpaTest + TestContainers）：加 saveMetadata(pubId, fullTextUrl) helper，断言 model.fullTextUrl()、model.provenanceCode() 从真实 SQL 取出

4. 前端：数据层

沿用 PAP-44 的「零映射 wire type + 纯函数 derive 视图层」。

4.1 wire type（src/types/portal.ts）

新增 PaperDetail 接口，完整镜像补齐后的 BE DTO（字段名直传、零运行时映射、id 为 string 防 JS 精度损失），及子类型：

  • EvidenceLevel { level: string; rank: number; label: string; derived: boolean }
  • AbstractSection { label: string; text: string }
  • Author { order: number; first: boolean; corresponding: boolean; name: string; affiliation: string | null }
  • MeshHeading { descriptorUi: string; term: string; major: boolean }
  • Funding { funder: string | null; grantId: string | null; country: string | null }
  • PublicationDate { type: string; date: string }

PaperDetail 含上述列表字段 + 扁平标量：id / title / originalTitle / venueId / venueName / publicationYear / evidenceLevel / abstractType / abstractSections / abstractPlainText / doi / pmid / pmcid / pii / primaryType / publicationTypes / citationCount / numberOfReferences / conflictOfInterest / isOa / oaStatus / aiSummary / source / fullTextUrl / bookmarks / estimatedReadMin。

4.2 fetch（src/lib/portal-api/publications.ts）

新增 fetchPublicationDetail(id: string): Promise<PaperDetail | null>，完全镜像 fetchVenueDetail：

  • 非数字 id（!/^\d+$/.test(id)）→ 直接 return null，不发 HTTP
  • 读 process.env.PATRA_GATEWAY_BASE_URL，缺失则 throw
  • URL：${baseUrl}/patra-catalog/portal/publications/${id}
  • fetch(url, { cache: "no-store", signal: AbortSignal.timeout(10_000) })
  • res.status === 404 → return null；其他非 2xx → throw（冒泡到 error boundary）
  • 成功 → return (await res.json()) as PaperDetail
  • 文件已有 import "server-only"

4.3 derive 层（src/lib/portal-api/publication-derive.ts，新建）

纯函数，把扁平 DTO 重组为组件视图对象（无副作用、可单测）：

  • deriveAbstract(p) → { kind: "structured" | "plain" | "empty"; sections?; text? }，三态判定（有 abstractSections → structured；有 abstractPlainText → plain；都无 → empty）
  • deriveEvidence(level) → { tone: "moss"|"amber"|"slate"|"muted"; lit: number; label; en; derived }，按 rank 映射色温与阶梯点亮数（lit = rank（rank 0–5，越大越强；clamp 到 [0,5]））
  • deriveFullTextHref(p) → string | null，优先级：fullTextUrl → https://doi.org/{doi} → https://pubmed.ncbi.nlm.nih.gov/{pmid} → null（落地「专门字段优先、其他途径降级」）
  • deriveBylineAuthors(authors) → 前 3 位 + 「等 N 位」溢出文案

6. Mock / 占位策略

原则：无真实用户，缺数据字段一律诚实占位（null/0 + TODO），绝不向用户展示伪造的聚合数据；BE 模型保持齐全，以后接入只填值不改契约。

区域数据现状本版渲染
AI 速读卡aiSummary 恒 nullclay accent 卡 +「mock · 占位」标注；null → 斜体灰「尚未生成 AI 速读」；「生成速读」按钮为静态占位（无 LLM 调用）
收藏按钮无收藏系统Client useState 本地切换填充态（视觉反馈），纯 mock 无 API、无 toast
速览·收藏数bookmarks=0显示 0（不编造计数）
速览·阅读时间estimatedReadMin=null渲染 "—"（保留行位，不伪造时长）
去全文按钮fullTextUrl 可能为 null降级链 fullTextUrl → DOI → PubMed；全无 → 按钮禁用置灰

关键决策与备选

决策 1：零映射 wire type + 纯函数 derive 视图层

沿用 PAP-44 已验证的模式：TS 接口扁平镜像 BE DTO（零运行时映射），组件消费的视图对象（abstract 三态、evidence 色温阶梯、全文链接降级）由 publication-derive.ts 纯函数派生。

备选 A：组件内直接消费 BE DTO — 否决：abstract 三态判定、evidence rank→tone 映射等逻辑会散落各组件，难单测。
备选 B：在 TS 层做完整 DTO→ViewModel 映射 — 否决：双重维护字段，PAP-44 已证明「扁平 wire + 按需 derive」更省。

决策 2：后端补齐详情模型（真实 + 诚实占位），而非前端造数据

详情页需要的字段全部在 BE DTO 里齐全：source/fullTextUrl 接真实领域数据，bookmarks/estimatedReadMin 留 0/null + TODO 占位，仿照已有 aiSummary=null 先例。

备选 A：纯前端造 mock 数据填满速览 — 否决：用户明确要求 BE 模型齐全；前端造聚合数据是欺骗性假数据。
备选 B：缺字段前端直接不渲染、BE 不动 — 否决：模型不完整，未来接入要改契约 + 改前端，违背绿地「一次设计到最终形态」。

决策 3：全文链接 fullTextUrl 优先 + DOI/PubMed 降级

BE 暴露 cat_publication_metadata.full_text_url 专门字段为主，FE 降级链 fullTextUrl → doi.org/{doi} → pubmed/{pmid} → 禁用。

备选 A：仅 DOI — 否决：无 doi 的老 PubMed 记录拿不到全文入口。
备选 B：DOI + PMID 并列双按钮 — 否决：与 hi-fi 单「去全文」按钮设计不符，header 操作区更拥挤。

决策 4：收藏 / AI 速读纯前端 mock（无 toast 依赖）

收藏按钮用 useState 本地切换图标填充态做视觉反馈；AI 速读区静态占位 +「mock」标注。均无 API、无 toast 库依赖。

备选 A：接真实收藏/LLM API — 否决：无用户系统、无 LLM 接入，YAGNI。
备选 B：完全删除这两块 — 否决：PAP-45 明确要求「aiSummary / 收藏按 mock 占位渲染（边界 B/C）」。
