Portal 前后端集成：ExploreFeed 接入 catalog

📅 2026-05-25 🌿 feat/portal-backend-integration 🎯 spec draft
关键决策摘要

把 portal 首页「文献流」(ExploreFeed) 从 mock 数据切换为 catalog 真实数据，本轮只连这一个区块（Journals / TopicCloud / 统计数字仍 mock）。不引入 BFF：由 catalog 新增一个面向 portal 的 driving adapter（六边形架构），response DTO 字段直接对齐前端 Paper 类型，前端零字段映射。Portal 用 Next.js RSC 在服务端直接 fetch gateway，切 tab 走 URL searchParam 触发 RSC 重渲，本版不使用 BFF route、不使用 TanStack Query。catalog 现有 publication/venue 全套查询接口是无客户端调用的 demo 代码，连同测试一并删除。aiSummary（AI 摘要）与 estimatedReadMin（原文阅读时长）后端暂无数据来源，返回 null 并标记 TODO，禁止用原始 abstract 冒充。

1. 背景与现状

v0.4 (PR #106) 已落地 portal 首页全部 6 个区块（TopNav / Hero / TopicCloud / Journals / ExploreFeed / Footer），但数据全部来自 src/data/* 的 mock（handoff 阶段的设计稿数据）。后端 patra-catalog 服务已有完整的 publication / venue / author / abstract / publication_type 等数据表（V1–V7 Flyway 迁移），以及一组 PublicationController / VenueController REST 接口——但经 grep 确认，这些接口没有任何业务客户端调用（portal 用 mock，monorepo 内零跨服务引用），属于早期演示性质的 demo 代码。

本次目标：让首页「文献流」展示来自 catalog 的真实文献。这是 portal 第一次真正接入后端，需要确立 portal ↔ 后端的接入范式（架构、字段契约、错误边界），为后续 Journals / 搜索 / 详情页接入打样板。

项目为单人维护的绿地项目，无历史包袱、无向后兼容约束：demo 代码直接删除而非保留并行，字段命名与类型按最终形态设计。

2. 范围边界

In Scope
  • catalog 新增面向 portal 的文献流接口 GET /portal/publications?tab={recent|cited}
  • catalog 删除全部 demo 查询链路（publication/venue 的 adapter/app/domain/infra 四层 + 测试）
  • portal ExploreFeed 改为 RSC 服务端 fetch gateway，渲染真实文献
  • 切 tab 走 URL searchParam（recent / cited 两个 tab）
  • 前端类型 Paper 字段重命名与 null 化（aiSummary / estimatedReadMin / kind）
  • 删除 mock src/data/feed.ts
Out of Scope
  • Journals / TopicCloud / 首页统计数字（继续 mock）
  • Composer 真搜索（按回车仍 toast「功能即将上线」）
  • 文献详情页、bookmarks 真实业务（按钮仍 disabled，bookmarks 恒为 0）
  • trending tab（本版删除，待后端有热度信号再加）
  • LLM 摘要生成、全文采集 / 阅读时长真实估算
  • 用户系统 / 鉴权 / 限流 / 超时 / retry / 熔断 / 错误日志上报
  • TanStack Query（Provider 已接入但本版不调用）

3. 整体架构

浏览器只与 portal Next.js 服务通信，永远看不到 gateway / catalog 地址。Portal 服务端（Node 进程）直接 fetch gateway，gateway 经 Nacos 服务发现路由到 catalog。不引入 BFF route handler——单人项目无需 indirection，且字段映射已在后端 portal adapter 完成。

浏览器
  │  （只收到 SSR 渲染好的 HTML，看不到后端地址）
  ▼
Portal Next.js Server (Node 进程)
  ├─ app/page.tsx (RSC) 读 URL ?tab=recent
  │   └─ ExploreFeed (Server Component)
  │        └─ fetch(GATEWAY + /patra-catalog/portal/publications?tab=...)
  └─ explore-feed/tabs.tsx (Client)
       └─ 切 tab → router.push('/?tab=cited') → Next.js 重渲上面 RSC 子树
  │  （服务端进程内网调用）
  ▼
patra-gateway :9528  (Nacos LB)
  ▼
patra-catalog :6300
  └─ adapter/rest/portal/  ← 本次新增的 driving adapter
       PortalPublicationController → PortalPaperResponse[]（字段对齐前端 Paper）
  • portal adapter = 六边形架构的 driving adapter，在 catalog 进程内，不是独立的 BFF 服务。
  • 前端零字段映射：PortalPaperResponse 的 JSON 直接就是 Paper 形态，res.json() 后类型断言即可。
  • 切 tab 走 URL 状态：tab 由 ?tab= 表示，不用 Zustand / TanStack Query；好处是链接可分享、刷新保留、零客户端 fetch。代价是每次切 tab 触发一次服务端 RSC 重渲（streaming，无白屏）。
  • 环境变量 PATRA_GATEWAY_BASE_URL 仅服务端读取（无 NEXT_PUBLIC_ 前缀），浏览器拿不到。
  • mock 不留 fallback：gateway/catalog 不通时 RSC fetch 失败 → 渲染「加载失败」占位，而非掩盖问题。

Adapter 层：adapter/rest/portal/ 包，@Tag(name = "Portal") 与（已删的）admin 标签隔离。

// adapter/rest/portal/response/PortalPaperResponse.java
//   字段名/类型直接对齐前端 Paper，前端零映射
public record PortalPaperResponse(
    String id,            // Long.toString(id)，避免 JS 超 2^53 精度损失
    String title,
    String journal,       // ← venueName
    Integer year,         // ← publicationYear
    List<String> authors, // 全部作者（前端决定截多少）
    Integer cites,        // ← citationCount
    Integer bookmarks,    // 恒为 0（无用户系统）
    String doi, String pmid,
    String source,        // ← provenanceCode 硬码字典映射
    String aiSummary,     // null + TODO（等 LLM 摘要）
    Integer estimatedReadMin, // null + TODO（等原文采集/字数估算）
    String kind,          // ← studyType，可 null
    Integer minutesAgo) {}    // ← (now - lastSyncedAt).toMinutes()，可 null

// adapter/rest/portal/request/PortalPublicationListRequest.java
public record PortalPublicationListRequest(String tab, Integer page, Integer pageSize) {}

PortalApiConverter 关键转换：

  • source：硬码常量表 PUBMED→"PubMed" / EPMC→"Europe PMC" / CROSSREF→"Crossref"；字典外的 code 回退显示原值。加 TODO：后续接入 registry provenance 字典的规范方式。
  • aiSummary = null + // TODO(LLM-summary): 接入 LLM 摘要生成后填充
  • estimatedReadMin = null + // TODO(read-time): 接入原文采集/字数后估算原文阅读时长
  • minutesAgo：lastSyncedAt 为 null 时返回 null，否则 Duration.between(lastSyncedAt, Instant.now()).toMinutes()
  • id = Long.toString(model.id())

Infra 层：infra/adapter/read/PortalFeedReadAdapter.java 实现 PortalFeedReadPort。单次 SQL 查询（避免 N+1）join：cat_publication 主表 + LEFT JOIN cat_venue（venueName）+ 子查询 array_agg(display_name ORDER BY author_order)（作者全列表）+ 子查询 cat_publication_type 按 type_order asc, id asc 取第一个 type_value。排序：RECENT → last_synced_at DESC NULLS LAST, id DESC；CITED → citation_count DESC NULLS LAST, id DESC。具体实现（JPQL / 原生 SQL）由 plan 阶段定。

6. 关键决策与备选

决策 1：不引入 BFF，由后端 portal adapter 提供对齐前端的 response

catalog 新增面向 portal 的 driving adapter，PortalPaperResponse 字段直接是 Paper 形态，前端零字段映射。

备选 A：Next.js BFF route handler 转发 + 字段映射 — 否决：单人项目无需 indirection，字段映射放后端只做一次（放浏览器则每用户一次）。
备选 B：浏览器直连 gateway — 否决：暴露后端地址、需配 CORS、丧失 SSR 首屏。

决策 2：demo 查询链路直接删除，不保留并行

现有 publication/venue 全套查询接口无客户端调用，连测试整链删除。

备选：保留 demo 与 portal adapter 并行 — 否决：绿地项目零客户端调用即死代码，违反「只维护当前版本」。

决策 3：切 tab 走 URL searchParam + RSC 重渲

tab 状态由 ?tab= 表示，client Tabs 触发 router.push，服务端重渲 ExploreFeed 子树。本版不使用 TanStack Query。

备选：client state + TanStack Query 客户端 fetch — 否决：本版无客户端 fetch 需求，URL 状态可分享/可刷新保留，更简单。

决策 4：aiSummary / estimatedReadMin 返回 null + TODO

后端无 LLM 摘要、无原文长度数据，两字段返回 null 并各自标 TODO（理由不同）。前端 aiSummary 为 null 时隐藏整个 badge。

备选 A：用原始 abstract 冒充 aiSummary — 否决：语义错误（abstract ≠ AI 速读），用户明确禁止改逻辑。
备选 B：砍掉这两个字段 — 否决：未来要做，字段契约先留位。

决策 5：provenance 映射硬码在 PortalApiConverter

PUBMED/EPMC/CROSSREF → 展示名，常量表硬码，加 TODO 待规范处理。

备选：catalog 经 HTTP Interface 查 registry provenance 字典 — 否决：YAGNI，code 数量极少；后续有规范的字典驱动方式时再改（已留 TODO）。

决策 6：authors 全返回，删除 authorCount 字段

后端返回完整作者列表，截断展示策略归前端（authors.length 即总数）。

备选：后端截前 3 人 + 返回 authorCount — 否决：截断属展示逻辑，不应固化在 API 契约里。

7. 风险与缓解

风险等级缓解
catalog 数据库无 publication 数据，首页文献流为空，看不出连通 mid 用户确认会有真实数据；plan 阶段把「publication 表非空」列为实施前置条件
删除范围误伤内部使用代码 mid 已 grep 确认 VenueEnrichment 系列保留、monorepo 内零跨服务引用；删除后跑全量编译 + 测试验证
provenance_code / studyType 实际取值与假设不符，映射不全 low source 字典外回退显示原值；kind 为 null 隐藏标签；plan 阶段查实际数据核对取值
单查询 array_agg 子查询在大数据量下性能退化 low 分页限制每页 ≤50；现有索引覆盖 join 键；本版数据量小，后续可优化为两段查询
RSC fetch 无超时，gateway/catalog 挂起会阻塞首页渲染 low 本版接受（内网调用）；try/catch 兜底渲染「加载失败」占位，不阻断其它区块；超时配置列入后续
