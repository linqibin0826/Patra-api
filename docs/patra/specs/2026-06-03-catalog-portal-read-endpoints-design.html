Catalog Portal 读端点设计：期刊/文献详情 + 期刊浏览检索

📅 2026-06-03 🌿 pap-42-be-portal-read-endpoints 👤 Lin 🎫 PAP-42 🎯 spec draft
关键决策摘要

为 v0.5 门户在 catalog 服务新增三条 portal 读端点：期刊详情 GET /portal/venues/{id}、文献详情 GET /portal/publications/{id}、期刊浏览/检索 GET /portal/venues（PageResult）。沿用既有 CQRS 读侧模式（domain ReadPort → infra ReadAdapter+JPA projection → app QueryService → adapter controller）。归并 topN 端点：浏览端点 subsumes 原 ?topN，首页改读 ?sort=impactFactor&pageSize=6。详情端点按渐进式披露策略一次返回完整数据集（含深数据层）。evidenceLevel 为读时 Domain 层衍生（不落库），homepageUrl 本版恒 null（采集另开 ingest issue）。全程 TDD。

1. 背景与现状

v0.5「Portal Detail Pages」要让访客从首页点开期刊/文献进入详情页、并提供期刊浏览检索页（Design 阶段 PAP-40/41/46 的 Claude Design hi-fi 已交付）。catalog 服务当前 portal 读侧仅有两个端点：GET /portal/venues?topN（首页 Top 期刊，返回 List<PortalVenueResponse>）与 GET /portal/publications（首页 explore-feed，返回 PageResult<PortalPaperResponse>）。

读侧已是成熟的 CQRS 模式：Domain 层定义 XxxReadModel（record）+ XxxReadPort（domain/port/read），Infra 层用 native query + JPA interface projection 一次性组装（无 @Entity 聚合加载、无 N+1），App 层 XxxQueryService（无接口、无 @Transactional）编排并归一化分页，Adapter 层 controller + PortalApiConverter 映射 response。分页统一用 PagingParams / PageResult<T>（linqibin-commons-core）。

DB（catalog 库）数据齐备：期刊有 cat_venue 主表 + JCR/CAS/Scopus 三套评级表 + 年度趋势 cat_venue_publication_stats + 标识符/期号表，publication_profile/citation_metrics/open_access 以 JSONB 存于主表；文献有 cat_publication 主表 + 摘要（structured_sections JSONB 扁平 kv）/作者+机构/标识符/类型(MeSH)/MeSH heading/关键词/资助/多类型日期等子表，cat_publication.venue_id 直挂 cat_venue。关键缺口：全库无期刊官网 homepageUrl 列；evidenceLevel 为衍生概念（DB 无此字段，但 cat_publication_type 的 MeSH 类型词汇足以推算）。VenueDao.findFilteredJournalPage() 已实现带 facet 过滤 + 四维排序的分页查询，仅未被 portal 端点暴露。

2. 范围边界

In Scope
  • 期刊详情 GET /portal/venues/{id} + 文献详情 GET /portal/publications/{id}（各配独立大而全详情 DTO，含深数据层）
  • 期刊浏览/检索 GET /portal/venues（分页 + 刊名搜索 q + 排序 + facet 过滤），返回 PageResult
  • 归并 topN：删除原 topN List 端点形态；首页 FE 取数迁移到浏览端点（与本 BE 改动同批落地）
  • evidenceLevel 读时衍生（Domain 层 EvidenceLevel.classify()）
  • VenueDao 扩排序维度（刊名 A–Z、中科院分区）
  • by-id not-found → CATALOG-0404 错误映射
  • 三端点 TDD：Domain 单测 + Adapter 切片测 + Controller 测
Out of Scope
  • homepageUrl 采集：详情 DTO 带字段但恒 null；不加 DB 列、不碰 ingest。采集另开 ingest issue。
  • facet 计数（cross-facet count）：本版 facet 仅作过滤，不做服务端聚合计数；FE 角标占位但不接数。
  • aiSummary（边界 B，恒 null）、收藏/书签（边界 C，不返回）
  • FE 详情页/浏览页实现（PAP-44/45/47）、全局 404/错误屏 FE 落地
  • 文献检索结果页 / 主题聚合页 / 该刊收录文献列表（非本版）

3. 端点设计

端点用途返回查不到 / 空
GET /portal/venues/{id} 期刊详情 PortalVenueDetailResponse 404（CATALOG-0404）
GET /portal/publications/{id} 文献详情 PortalPublicationDetailResponse 404（CATALOG-0404）
GET /portal/venues 期刊浏览/检索（含首页 Top） PageResult<PortalVenueBrowseResponse> 空 PageResult（200，items:[]）

浏览端点入参：q（刊名/缩写模糊）、sort（impactFactor | casQuartile | title | citedBy）、page / pageSize（PagingParams.normalize 归一化）、facet：subject（JCR subject）、jcrQuartile、casQuartile、casTop、openAccess、doaj、country。

topN 归并：原 GET /portal/venues?topN=6（返回 List）删除；首页「IF Top 6」改为 GET /portal/venues?sort=impactFactor&pageSize=6 取 .items。浏览卡片字段是首页卡片的超集，兼容。经 gateway 实际路径为 /patra-catalog/portal/venues（StripPrefix=1）。

为什么详情端点一次返回全量

按 patra-portal/CLAUDE.md 渐进式披露策略的 BE 连带含义：详情类端点一次返回完整数据集（含深数据层），由前端按需折叠披露，避免多次往返。故两个详情 DTO 是「大而全」结构。

4. DTO 字段分层

详情 DTO 在结构上不区分「默认/深数据」（一次返回全量），下表的分层仅标注 FE 的披露层级，便于核对字段来源。

4.1 PortalVenueDetailResponse（期刊详情）

层级字段来源
默认层id, title, abbreviatedTitle, venueType, issnList, country/countryName, primaryLanguage, foundedYear, subjectAreas, coverUrl, isOpenAccess, homepageUrl=nullcat_venue 主表 + cat_venue_identifier + publication_profile JSONB
默认层metrics：jcr{impactFactor,quartile,percentile,rank,subject}、cas{majorCategory,majorQuartile,minorSubject,minorQuartile,isTop,isReview}、scopus{citeScore,sjr,snip,percentile}、bibliometric{hIndex,i10Index,citedByCount,worksCount}三套评级表最新年 + citation_metrics JSONB
深数据层completeRatings（多年 JCR/CAS/Scopus 列表）、yearlyStats（年度发文/被引）、publicationProfile（frequency/medlineIndexed/languages/startYear）、openAccess（oaType/apcUsd/isInDoaj）、affiliatedSocieties、identifiers、casWarning评级表全量 + cat_venue_publication_stats + JSONB

边界aiSummary=null（边界 B）、收藏不返回（边界 C）—

4.3 PortalVenueBrowseResponse（浏览卡片）

id, name, abbr, cover, impactFactor, jcrQuartile, jcrSubject, casMajor, casQuartile, casIsTop, country, citedTotal, publisher, foundedYear, isOpenAccess, isInDoaj, issn。

4.4 结构化摘要映射

cat_publication_abstract.structured_sections 是 JSONB 扁平 kv（key=节标题如 BACKGROUND，value=节文本），节名来自 PubMed 无固定枚举。→ DTO 映射为有序数组 sections: [{label, text}] 保留原始/入库节序；plainText 作无结构摘要 fallback。前端不依赖固定枚举。

5. 六边形落地

三条读流各自一套，沿用现有读侧分层；包路径见 .claude/rules/tech/port-service.md（ReadPort 在 domain/port/read，ReadAdapter 在 infra/adapter/read）。

5.1 期刊详情

VenueDetailReadModel(domain/model/read/portal) → VenueDetailReadPort(domain/port/read，Optional<VenueDetailReadModel> findById(long)) → VenueDetailReadAdapter + projection(infra/adapter/read，主表 + 多评级表 + 年度趋势 LATERAL/批量子查询) → VenueDao 扩查 → PortalVenueDetailQueryService(app，空 Optional 抛 NOT_FOUND) → PortalVenueController#getById + PortalVenueDetailResponse。

5.2 文献详情

PublicationDetailReadModel（含 EvidenceLevel 衍生字段）→ PublicationDetailReadPort → PublicationDetailReadAdapter（abstract / authors+affiliation / types / mesh / keywords / funding / dates 子查询，structured_sections JSONB→有序数组）→ PortalPublicationDetailQueryService → PortalPublicationController#getById + PortalPublicationDetailResponse。

5.3 期刊浏览

VenueBrowseFilter(record) + VenueBrowseSort(enum：IMPACT_FACTOR/CAS_QUARTILE/TITLE/CITED_BY) → VenueBrowseReadPort(PageResult<VenueBrowseReadModel> search(filter, PagingParams)) → VenueBrowseReadAdapter 复用 VenueDao.findFilteredJournalPage（扩 TITLE / CAS_QUARTILE 两种 ORDER BY）→ PortalVenueQueryService 扩展 → PortalVenueController#list(PageResult) + PortalVenueBrowseResponse。原 PortalVenueResponse / findTopByImpactFactor 链路删除/重写。

6. evidenceLevel 衍生

Domain 层 EvidenceLevel.classify(List<String> typeCodes)，输入取 cat_publication_type（MeSH UI + 标准词汇，多值），多类型取最强档；带 derived=true 标记，无法判定 → UNKNOWN（降级态，绝不臆造）。映射表（已确认）：

档（设计稿格数）证据等级命中类型（MeSH 词汇）
5 格系统综述 / Meta 分析Systematic Review, Meta-Analysis, Scoping Review
4 格随机对照试验Randomized Controlled Trial
3 格队列 / 病例对照Cohort Study, Case-Control Study, Observational Study
2 格非系统综述 / 横断面Review, Cross-Sectional Study, Clinical Trial（非 RCT）
1 格病例报告Case Reports
unknown无法判定其余（Editorial / Letter / Comment…）

关键决策与备选

决策 1：归并 topN，浏览端点 subsume 首页 Top

GET /portal/venues 改为浏览端点（PageResult），删除原 topN List 形态；首页 Top 6 改读 ?sort=impactFactor&pageSize=6。

备选 A：浏览另用同路径 + 首页保留 GET /portal/venues/top(List) 并存 — 否决：两个期刊列表端点并存，违背绿地「不留并行实现」。
代价：首页 FE 取数须同批迁移（删端点后首页会断），smoke test 验首页。

决策 2：evidenceLevel 读时衍生（Domain 层），不落库

读模型组装时调 EvidenceLevel.classify() 实时推算。

备选 A：ingest 时计算并持久化 — 否决：规则调整须全量回填；绿地+详情低 QPS 无须预计算。

决策 3：结构化摘要映射为有序数组

JSONB 扁平 kv → sections: [{label, text}] 保留节序 + plainText fallback。

备选 A：Map<String,String> 原样透传 — 否决：丢失节序，阅读体验差。

决策 4：homepageUrl 读端恒 null，不加列、采集另开

详情 DTO 带 homepageUrl 字段但恒 null，FE 降级（按钮 disabled + tooltip）。

备选 A：本版加列 + 从 OpenAlex source 回填 — 否决：超出读端范围、引入 ingest 工作量。
备选 B：彻底删字段 — 否决：与已交付设计（按钮含 null 降级）不一致。

决策 5：facet 计数本版不实现

facet 仅作过滤；FE 角标占位但不接数。

备选 A：服务端 cross-facet 聚合计数 — 否决：handoff 的计数属「锦上添花」（不在简报），分页下需额外聚合查询，非本版必要。

决策 6：「学科」facet 用 JCR subject

浏览 subject facet 取 JCR rating 的 subject。

备选 A：CAS major_category（中文学科大类）— 用户选定 JCR subject。

风险与缓解

风险等级缓解
删 topN 端点后首页未同步改取数 → 首页期刊模块断 mid BE 删端点与首页 FE 取数迁移同 PR/同批落地；smoke test 验首页 Top 6 渲染
evidenceLevel 衍生误判（临床敏感标签） mid 带「衍生」标记 + UNKNOWN 降级；映射表经人工确认；Domain 单测覆盖各档 + 多类型取最强 + unknown
structured_sections 节名跨文章不一致、无固定枚举 low 有序数组原样透传 label，前端不依赖固定枚举
文献详情多子查询（authors/mesh/funding/dates）性能/N+1 low 详情低 QPS；projection + 批量子查询/LATERAL JOIN，避免循环单查
homepageUrl 恒 null 影响期刊页主操作观感 low FE 已设计 disabled + tooltip 降级；采集 backlog 跟进
