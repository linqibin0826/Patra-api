摘要/标题内联标签白名单渲染

📅 2026-08-29 🌿 feat/inline-tag-rendering 👤 linqibin 🎯 spec draft
关键决策摘要

PubMed 保真落库的内联标签（<sub>/<sup>/<i>/<b>/<u> 及 MathML 公式）目前在 portal 被当纯文本渲染，标签裸露在页面上。本设计新建零依赖的白名单渲染器：纯函数解析器 parseInlineMarkup + RSC 兼容组件 RichInlineText，排版 5 标签任意位置放行，MathML Core 标签集仅在 <math> 子树内放行（浏览器原生渲染），属性全剥、实体顺手解码、白名单外一律按字面文本显示，禁 dangerouslySetInnerHTML。现有 4 个渲染点全部接入，日后新页面复用同一组件。

1. 背景与现状

v0.6 作者与摘要数据链路修复时，PubMed 标题/摘要中的内联排版标签被刻意保真落库（下标、上标、斜体物种名等信息有语义价值，不是数据 bug）。但 portal 侧所有标题与摘要均以 {text} 纯文本渲染，React 自动转义使标签原样露出，用户看到 CO<sub>2</sub> 而非 CO2。

2026-08-29 对 mini 生产库（patra_catalog）实测的数据分布：

情况规模说明
排版标签（i/b/sub/sup/u）1,132/18,807 标题（6%）；4,481/15,653 摘要（29%）标题只出现 i/sub/sup/b 四种，非常干净；摘要另有 34 处 <u>
MathML 公式21 个摘要（存量）<math><msub><mi>μ</mi>…，部分带 <semantics>/<annotation>$$LaTeX$$</annotation>；采集持续进行，绝对数量随数据增长
正文中的裸 <散在各处（几十处）如 "P <median"、"<0.05"、"<fib-4"——不是标签，是小于号，渲染时必须字面保留
残留 HTML 实体10 个摘要如文本里存的是 &amp;，页面显示成字面 &amp;

aiSummary 全链路恒为 null（BE 无 LLM 摘要数据源），页面 <title> metadata 不从文献标题生成，两者均不在本次范围内。

2. 范围边界

In Scope
  • 纯函数解析器 parseInlineMarkup(text): InlineNode[]（零第三方依赖）
  • RSC 兼容渲染组件 <RichInlineText text={...} />
  • 排版标签白名单：i / b / sub / sup / u
  • MathML Core 标签集白名单（仅 <math> 子树内），浏览器原生渲染
  • 常见 HTML 实体解码（命名 + 十进制 + 十六进制）
  • 接入现有 4 个渲染点：PaperCard 标题、PaperHeader 标题+原文标题、AbstractBlock 纯文本态与结构化段落态
  • 解析器纯函数测试 + 组件渲染测试（TDD）
Out of Scope
  • BE / 数据链路改动——数据保真落库是既定正确行为，本次只改渲染端
  • aiSummary（恒 null，无数据源）、页面 <title> metadata（不存在）
  • LaTeX 渲染引擎（KaTeX/MathJax 等）——浏览器原生 MathML 已足够，annotation 里的 LaTeX 重复表述直接丢弃
  • venue / 期刊侧字段（实测无标签）、COI 字段（实测无标签）、keywords、MeSH
  • sub/sup 行高微调等视觉打磨——浏览器默认样式先行，实检有问题再说

3. 组件结构

patra-portal/src/
├── lib/rich-inline-text.ts               ← 纯解析器：parseInlineMarkup(text) → InlineNode[]
│                                            纯 TS 函数，无 React 依赖，可独立测试
└── components/portal/RichInlineText.tsx  ← 渲染组件：<RichInlineText text={...} />
                                             InlineNode[] → React 元素树，RSC 兼容（无 "use client"）

解析与渲染分两层：解析器输出轻量节点树（文本节点 + 元素节点，元素节点含标签名与子节点），组件递归把树变成 React 元素。解析器的全部边界行为用纯函数测试钉死，不需要起 DOM。

InlineNode 形态（示意）：

type InlineNode =
  | { kind: "text"; value: string }                          // 文本（实体已解码）
  | { kind: "element"; tag: string; children: InlineNode[] } // 白名单元素（属性已剥）

组件只输出内联元素、不带任何布局样式，外围字体/字号/行高/颜色由调用处现有 class 控制，嵌入现有排版即插即用。

4. 解析器行为规格

4.1 白名单（两组）

组标签放行条件渲染
排版组 i b sub sup u 任何位置 同名 HTML 元素
公式组 math mrow mi mo mn msub msup msubsup mtext mspace mstyle mover munder munderover mfrac msqrt semantics annotation 仅在 <math> 子树内；游离在公式外按字面文本 浏览器原生 MathML Core

4.2 铁律与降级规则

  1. 属性全剥：<i class="x" onclick="…"> 认标签、丢全部属性，渲染成干净 <i>——不存在任何属性攻击面（含 MathML 的 display，公式强制随文内联）
  2. 不认识 = 字面文本：<0.05、P <median、<fib-4>、<script> 等一切白名单外内容原样当文字显示，一个字符都不吞
  3. 未闭合标签：开了没关（<i>abc 到结尾）→ 格式生效到段尾自动闭合；孤儿闭合标签（</i> 前面没开）→ 按字面文本显示
  4. semantics/annotation 特判：已闭合的 <annotation> 内容整体丢弃（它是同一公式的 LaTeX 重复表述，渲染会导致公式显示两遍）；未闭合的 <annotation>（上游截断形态）只展开子节点不删除，保证正文一个字符不丢；<semantics> 渲染其余子节点
  5. 实体解码：文本段里 &amp; &lt; &gt; &quot; &apos; 及数字/十六进制实体（&#8722; / &#x2212;）解码回真字符；解码出的 < 是文本节点，天然安全
  6. 大小写不敏感：<SUP> 也认，标签名归一化为小写
  7. 禁 dangerouslySetInnerHTML：输出 React 元素树，文本内容由 React 自动转义——这是方案不可能 XSS 的根本保证

4.3 嵌套

白名单标签任意嵌套（如 <i><sub>…</sub></i>）以栈式解析支持；闭合标签与栈顶不匹配时，弹栈直到匹配（中间未闭合的自动闭合），栈内无匹配则该闭合标签按字面文本处理。

5. 渲染点接入

文件现状改为
PaperCard.tsx（Feed 卡片标题）{paper.title}<RichInlineText text={paper.title} />
PaperHeader.tsx（详情页主标题 + 原文标题）{paper.title} / {paper.originalTitle}同上，两处
AbstractBlock.tsx（纯文本摘要态）{abstract.text}<RichInlineText text={abstract.text} />
AbstractBlock.tsx（结构化段落态）{s.text}同上（有 label / 无 label 两分支各一处）

段落 label（BACKGROUND/METHODS 等）是自有枚举值，不含标签，不接。日后任何新页面显示标题/摘要，直接复用 RichInlineText。

6. 测试策略（TDD）

6.1 解析器纯函数测试（主战场，Vitest，不起 DOM）

  • 无标签文本原样通过；每个排版标签单测；嵌套 <i><sub>…</sub></i>
  • 降级铁律逐条钉死：裸 <（P <median、<0.05）字面保留；白名单外标签（<script>、<fib-4>）字面保留；未闭合自动闭合；孤儿闭合按字面
  • 属性剥离：<i class="x" onclick="…"> → 干净 <i>
  • 实体解码：命名 + 十进制 + 十六进制；&lt; 解出的 < 是文本节点
  • MathML 金样本：生产库真实样本（<math><msub><mi>μ</mi>… 与带 semantics/annotation 的样本）；annotation 内容被丢弃；游离在 <math> 外的 <mi> 按字面
  • 安全反例：<img src=x onerror=…>、<a href="javascript:…"> 必须字面显示

6.2 组件渲染测试（Testing Library，少量）

  • CO<sub>2</sub> 渲染出真实 <sub> 元素
  • 恶意输入渲染后 DOM 里不存在 script/img 元素

6.3 改造点验证

  • 现有测试保持绿色
  • 浏览器实检：mini 真实数据（带标签的 4,481 篇摘要 / 1,132 个标题中挑样本，含 MathML 摘要）

7. 关键决策与备选

决策 1：自写零依赖白名单解析器，输出 React 元素

约 150–200 行栈式解析器：识别白名单标签、递归嵌套、其余按字面文本输出。零第三方依赖、RSC 天然兼容、坏数据降级行为 100% 可控（"不认识就当文字"是默认行为而非补丁）。

备选 A：DOMPurify + dangerouslySetInnerHTML — 否决：违反既定安全铁律（禁裸注入），且 DOMPurify 面向浏览器 DOM，RSC 侧需额外适配。
备选 B：html-react-parser + 白名单配置 — 否决：依赖链重（htmlparser2 等）却只用其 5% 能力；按"宽容 HTML"语义解析，正文里大量裸 < 的降级行为不受控（可能吞字符），反而要打补丁对抗库行为。

决策 2：MathML 原生渲染而非剥标签降级

MathML Core 标签集入白名单（仅 <math> 子树内），交给现代浏览器（Chrome/Safari/Firefox 均原生支持）渲染，属性全剥。21 篇是当前存量，采集持续进行，绝对数量会一直涨；质量优先原则下一次做对，老浏览器不认识时天然降级为平铺文本，无更坏结果。

备选 A：剥标签保内容（μmax 平铺成 μmax）— 否决：丢失公式结构，且数据增长后需返工。
备选 B：整段公式占位降级（标灰等宽显示）— 否决：引入特判逻辑，体验不如原生渲染。

决策 3：MathML 标签仅在 math 子树内放行

游离在 <math> 外的 <mi> 等按字面文本处理。白名单语义更紧：排版组是通用内联标签，公式组只有在公式上下文中才有意义，脱离上下文放行只会造出无意义的未知元素。

备选：单一扁平白名单（mi 任意位置放行）— 否决：实现略简但语义松，脏数据里孤立 <mi> 会被静默转成 DOM 元素而非可见文本，违背"不认识就当文字"的直觉。

决策 4：顺手解码 HTML 实体

解析器在文本段解码常见命名实体与数字/十六进制实体，10 篇残留实体的摘要一并修复。成本极小，解码结果进文本节点，安全性不受影响。

备选：只管标签不管实体 — 否决：留字面 &amp; 的小瘤，修复成本与顺手做几乎相同。

8. 风险与缓解

风险等级缓解
自写解析器边界情况遗漏（诡异嵌套、深度嵌套、超长文本） mid TDD 先行 + 生产库真实脏样本做金样本测试；默认行为是"不认识就当文字"，漏网结果最多是显示原文（等同现状），不会更坏
XSS：脏数据经渲染器变成可执行内容 low 输出 React 元素树 + 属性全剥 + 白名单封闭集合，无 dangerouslySetInnerHTML；安全反例入测试固定
MathML 在旧浏览器/爬虫渲染异常 low 未知元素的浏览器默认行为即平铺内联文本，天然降级等同"剥标签保内容"方案
sub/sup 撑坏现有行高排版 low 浏览器默认 sub/sup 样式先行，接入后浏览器实检，有问题再局部微调（明确列为后续可选项而非本次范围）
